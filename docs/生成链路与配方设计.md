# 生成链路与配方（Recipe）设计

> 状态：讨论中（2026-08-23）
> 前置文档：[指令体系与生成架构规划.md](./指令体系与生成架构规划.md)
> 总原则：整个生成链路可以推翻重来，按用户需求设计——大量制作、内容为王、新课标可直接用、流水线化、源头解决、不靠打补丁。

## 一、一次调用 vs 逐板块调用（利弊全景）

| 维度 | 一次调用（整卷生成） | 逐板块调用（分步生成） |
|---|---|---|
| 上下文一致性 | ✅ 整卷情境统一、跨板块可呼应、考点全局去重 | ❌ 各板块独立决策，易情境割裂、考点跨板块重复 |
| 指令执行率 | ❌ 长指令 Lost in the Middle，中部约束被忽略 | ✅ ~600 token 短指令，约束聚焦、执行率高 |
| 输出质量稳定性 | ❌ 长输出后半段质量衰减（生成衰减） | ✅ 每板块长度受控，质量稳定 |
| 约束稀释 | ❌ 红线被几十条约束稀释 | ✅ 红线集中前置，板块内不稀释 |
| 失败成本 | ❌ 一次失败全卷失败，重试整卷、token 浪费大 | ✅ 单板块失败只重试该板块（2次），成本低 |
| 局部修复 | ❌ 质检发现问题需整卷重传修复，消耗大 | ✅ 天然支持"只重生成问题板块" |
| 流水线化 | ❌ 难做"每步可验证、可重试、可并行" | ✅ 规划→生成→拼接→质检，每步独立可验证、可并行 |
| 素材精准度 | ❌ 全卷一次检索，素材粒度粗 | ✅ 每板块按本板块考点精准检索，内容贴 |
| 角色分工 | ❌ 一个模型干所有事 | ✅ 命题/教辅/阅卷/讲解分角色调用 |
| 调用延迟 | ✅ 1 次往返 | ❌ N 板块 = N 次往返（可用并行缓解） |
| 全局统筹 | ✅ 规划与执行一体 | ❌ 规划必须前置做扎实（考点分配/去重/难度曲线/情境主题） |

**结论（按用户需求）**：生产工具 + 流水线 + 内容为王 → **逐板块调用为正解**，前提是两个补偿机制：
1. **全局统筹前置到规划层**（考点分配、跨板块去重、难度曲线、情境主题由数据计算，不靠 AI 自觉）；
2. **拼接与格式由代码保证**（卷首/密封线/编号/答案区锚定，不让 AI 拼）。

## 二、生成板块设计（按用户需求推导）

### 2.1 板块定义原则

1. **板块 = 可交付的教学/考查单元**：边界清晰、功能单一，每个板块对应一个明确课标功能（积累运用/阅读理解/综合探究…）。
2. **板块即"局部可重生成单元"**：质检不合格只重生成该板块，不波及其他。
3. **板块内容 = 检索素材 + 短指令**：素材（教材原文/例题/情境）由检索注入，AI 只做"基于素材的创作"——落实"内容为王"。
4. **板块列表 = 数据**：来自配方/蓝本，非 AI 规划（杜绝规划漂移）。
5. **板块可并行**：相互独立，支持并发调用，缩短总延迟。

### 2.2 板块类型（按 genType 分流）

| genType | 板块来源 | 板块示例 |
|---|---|---|
| exam | 真题卷蓝本（数据） | 一、积累与运用　二、阅读理解　三、写作 |
| practice | 教辅栏目（任务群） | 情境任务 / 基础型任务 / 发展型任务 / 拓展型任务 |
| special | 专项训练链 | 方法指导 / 典例剖析 / 阶梯训练 / 真题检验 |
| preview | 预学任务单 | 情境导入 / 预学任务 / 素养预备 / 我的问题 |
| reading | 阅读素养 | 语篇一（信息提取）/ 语篇二（深层理解）/ 语篇三（批判评价） |
| dictation | 语境积累 | 语境识记 / 积累运用 / 诵读积累 / 订正反思 |
| errorbook | 错题闭环 | 错题整理 / 精准归因 / 正确解法 / 变式巩固 / 方法归纳 |
| summary | 知识结构化 | 概念网络 / 易错辨析 / 典型例题 / 综合运用 |
| review | 大单元复习 | 知识框架 / 考点梳理 / 典型题析 / 易错聚焦 / 综合自测 |

### 2.3 板块生成流水线（每板块）

```
规划层(代码)  ──►  板块配方(数据)  ──►  素材检索(代码)  ──►  短指令(模板+素材)
                                                              │
                                                              ▼
                                                          调用 AI
                                                              │
                                                              ▼
                                      硬规则校验(代码) ◄── 板块 HTML
                                                              │ 不合格
                                                              ▼
                                                          局部重生成(≤2次)
```

## 三、规范数据模型：配方（Recipe）

### 3.1 设计思想

- **配方 = 一类资料的完整生成规范**（数据，非文本），运行时不改配方、只填实例参数。
- 配方**引用**规范块（角色/红线/品质/格式等），规范块仍是可维护文本，但组织由配方驱动。
- 三条生成路径（整卷/分步/答案）共用同一配方，差异只在"执行器"。

### 3.2 配方数据结构

```js
{
  // ── 元信息 ──
  meta: {
    id: 'recipe_exam_primary_low',      // 唯一 id
    name: '正式考卷·小学低段',
    genType: 'exam',                    // 资料类型
    stages: ['primary_low'],            // 适用学段（空=全部）
    subjects: ['语文'],                 // 适用学科（空=通用）
    version: 1,
  },

  // ── 角色与稳定规范（System 层）──
  role: {
    persona: '命题专家',                 // 角色称谓
    personaDesc: '经验丰富、符合2022版新课标素养立意',
    systemBlocks: ['role_exam', 'redline_exam', 'format_exam', 'topconst_exam', 'tailconst_exam'],
    // 引用规范块 id，注入 system prompt，全资料类型/全板块共享
  },

  // ── 蓝图（exam 专用；非 exam 用 sections 直接定义）──
  blueprint: {
    fullScore: 100,
    duration: 60,
    sealLine: true,                     // 是否含密封线
    header: 'assemblePaperHeader',      // 卷首拼装函数（代码）
    sections: [                         // 板块序列（数据，AI 不决策）
      { name: '一、积累与运用', questionCount: 8, score: 30 },
      { name: '二、阅读理解',   questionCount: 5, score: 40 },
      { name: '三、看图写话',   questionCount: 1, score: 30 },
    ],
  },

  // ── 板块定义（核心）──
  sections: [
    {
      id: 'sec_accumulate',
      name: '积累与运用',
      note: '本板块覆盖：字词积累、句式运用、课内积累',   // 板块说明（喂给 AI 的语境）
      questionCount: { min: 8, max: 12, rule: '按考点密度' }, // 题量规则
      score: { fixed: 30, rule: '小题分值之和=30，整数' },    // 分值规则
      kpPolicy: { mode: 'weight', by: '知识图谱', maxRepeat: 1 },
      // 考点策略：按知识图谱权重分配；同卷跨板块去重（同一知识点全卷≤1次，重难点≤2次）
      structure: '基础字词 → 句式运用 → 课内积累，由易到难',
      materials: {
        retrieval: { focus: 'kp', maxChars: 2000 },   // 按本板块考点检索教材原文
        samples: { library: 'examSampleLibrary', count: 2 }, // 真题样例
        context: { require: true },                    // 情境要求
      },
      format: {
        title: '一、积累与运用。（共X题，每题X分，共X分）', // 标题模板
        tags: 'question/option/blank',                 // 允许的 HTML 标签
      },
    },
    // ... 更多板块
  ],

  // ── 全局约束（跨板块，注入 system）──
  constraints: {
    redlines: ['原创命题', '不超纲', '无科学性错误', '知识点去重'],
    quality: ['素养立意', '设问层次', '情境真实'],
    format: ['填空标签规范', '小题标分规范', '禁止Markdown'],
  },

  // ── 素材策略 ──
  materialStrategy: {
    retrievalEngine: 'retrieveBlueprintSegments',
    semanticSearch: 'semanticRetriever',
    maxTotalChars: 6000,
    priority: 'propositionMaterial > 原文 > 例题情境',
  },

  // ── 质检门（代码执行，非 prompt 承诺）──
  qualityGate: {
    hardRules: [
      'score_sum',        // 分值加总=满分
      'blank_tags',       // 填空标签规范
      'question_wrap',    // 题目 p.question 包裹
      'option_count',     // 选项数量合规
      'kp_no_duplicate',  // 跨板块考点去重
      'header_match',     // 标题与蓝图一致
      'answer_section',   // 答案区完整
    ],
    thresholds: { minChars: 300, minSections: 1 },
    repair: { maxRounds: 1, scope: 'section' },  // 只修复问题板块
  },

  // ── 输出规范 ──
  output: {
    htmlTemplate: 'exam',       // 代码侧 HTML 骨架
    answerSection: true,
    answerRole: '阅卷专家',     // 答案页独立角色
    export: 'docx/pdf/html',    // 导出格式
  },
}
```

### 3.3 配方与规范块的关系

```
配方（Recipe，数据，可批量管理）
   │ 引用
   ▼
规范块（规范文本，可维护）
   role_* / redline_* / quality_* / format_* / topconst_* / tailconst_*
   │ 由派生器组装
   ▼
短指令（板块级，~600 token）= 板块模板 + 检索素材 + 引用规范
```

- 规范块 = 原子内容，配方 = 组装蓝图；两者解耦：改措辞只改规范块，改结构只改配方。
- 去掉：`buildGenerationInstruction` 中几十个 `getMatchingBlockInstructions` 的散点查询，改为配方驱动的统一派生器。

### 3.4 质检规则作为数据（从"事后打补丁"到"事前约束"）

```js
// 质检规则注册表（数据，可扩展）
qualityRules: {
  score_sum:        { check: 'sum(scores)===fullScore', severity: 'error', repair: 'regen-section' },
  blank_tags:       { check: 'blank-N 规则',            severity: 'error', repair: 'auto-fix' },
  kp_no_duplicate:  { check: '跨板块去重',              severity: 'error', repair: 'regen-section' },
  header_match:     { check: '标题===蓝图',             severity: 'error', repair: 'auto-fix' },
}
```

## 四、排版模块评估（2026-08-23 复核）

### 4.1 已合格部分（代码保证，保留）

| 项 | 实现 | 结论 |
|---|---|---|
| 密封线 | `docxBuilder` 密封线浮动群组（`wp:anchor` 页眉承载，不占文档流）；`TypesetModule` 结构归一化 + `sealed_exam` 主题包装 | ✅ 合格 |
| 答案区分节 | `ANSWER_SPLIT_MARKER` 哨兵拆分正文/答案两个 Word 分节，答案页独立编号从 1 起 | ✅ 合格 |
| 页码/页脚 | PAGE/SECTIONPAGES 域，正文"共X页"不含答案页 | ✅ 合格 |
| 卷首信息栏 | `assemblePaperHeader` 代码拼装（标题/时长/满分/密封线） | ✅ 合格 |
| 卷面固定件 | `injectExamShell` 注入注意事项 + 题号得分表，编辑/导出同路径幂等 | ✅ 合格 |
| 作文格/四线三格/田字格 | 按学段自动算格宽列数（小学 8mm/初中 7mm/高中 6mm） | ✅ 合格 |

### 4.2 缺口（需重弄）：编号仍由 AI 输出

现状：`buildSectionInstruction` 把标题模板（`<h2>一、XX。（共X题…）</h2>`）作为**要求**塞进指令，让 AI "原样保留"输出；小题题号（"题号从 1 开始连续编号"）也由 AI 生成；拼接时 `sectionsHtml.join('\n')` 直接拼装，无编号后处理。

**问题**：AI 若偏离（漏标题、跳号、改题数），编号就错；且这违背"拼接与格式由代码保证"的总原则。

**修复设计（配方架构下）**：

```
AI 输出（正文区，无标题无题号）
  <div class="section-body"> 题干/选项/空 … </div>
        │
        ▼
拼装器（代码，Pass 3）
  1. 包板块标题：<h2>一、积累与运用。（共8题，每题2分，共16分）</h2>   ← 序号/题数/分值来自配方
  2. 小题重编号：遍历 .question，按蓝图题号重排（1.2.3…）            ← 代码写题号
  3. 分值标注校验：题干末尾（X分）缺失则按配方补/标错           ← 硬规则
  4. 答案区锚定：<div class="answer-section"> 由代码包裹
```

- AI 输出契约收窄为：**只写题干、选项、空标签**（`question/option/blank`），不写标题、不编号、不写答案。
- 编号、标题、分值标注、答案区结构全部由拼装器代码生成——彻底"不让 AI 拼"。
- 质检规则 `header_match`（标题===配方）从"校验 AI"降级为"校验拼装器"，永不出错。

### 4.3 与配方的关系

- 排版导出层（TypesetModule/docxBuilder）**保留不动**——它已是正确的"渲染器"。
- 需要改动的是**生成→拼装的边界**：`buildSectionInstruction` 移除标题/编号要求（AI 只写内容），新增 `assembleSections`（拼装器）承接标题包裹 + 重编号 + 答案锚定。
- 配方 `output` 字段扩展：`heading: { byCode: true }`、`numbering: { byCode: true }`、`answerAnchor: { byCode: true }`——显式声明这些由代码保证，AI 契约中明确排除。

### 4.4 两条设计约束（2026-08-23 确认）

#### 约束1：规划数据与卷面输出通道隔离（防泄漏）

规划数据（考点→板块、题量、分值、认知层级）只存在于两条通道，**不通往卷面 HTML**：

```
规划数据（plans[]）
   ├─ 通道A：派生器 → AI 短指令（生成依据）
   ├─ 通道B：界面预览（生产计划可视化）
   └─ ✗ 不进入卷面（拼装器只组装卷面允许的内容）
```

- 卷面 HTML 由拼装器代码组装，规划数据不在其输入范围内。
- 现有 prompt 红线（topconst_exam 第1条/quality_redlines_exam ②"卷面严禁输出知识点/层级标注"）升级为**代码级"卷面净化"**：生成后扫描并删除正文中的考点名/认知层级/单元标注，注册进 `qualityGate.hardRules`。
- 界面预览是"生产计划可视化"（编辑/用户可见），与最终卷面物理隔离。

#### 约束2：确定性分层——结构确定、内容多样

| 层 | 负责方 | 确定性 |
|---|---|---|
| 结构层（板块/标题/编号/分值/考点分配/答案锚定） | 规划器 + 拼装器（纯代码） | 100% 一致，同输入同输出 |
| 内容层（题干/选项/解析文字） | AI 生成（temperature 0.7） | 每次不同（特性） |

- 结构一致 = 可直接用/可排版/可归档/可质检，流水线稳定。
- 内容多样 = 同单元可批量产出 N 套不同卷，满足"大量制作"产能。
- 复现需求：固定 seed + temperature 0 可逐字复现（一般不需要）。

### 6.5 实测修复（2026-08-23 二次实测）

实测发现并修复 3 个 P0/P1 缺陷：

| 问题 | 根因 | 修复 |
|---|---|---|
| **没有题目，全是答案** | executor 把 `tailText`（"文末必须包含 answer-section 答案区"）拼到每个板块 prompt 尾部，诱导 AI 只出答案区 | 板块 prompt 不拼 tail；tail 仅注入答案页（`deriveAnswerInstruction`） |

| 指令含 `{diffRatio}` 字面量 | top 规范块占位符未替换 | deriver 注入 diffRatio（exam 默认 50/30/20，非 exam 用递进文案） |

### 6.6 二次实测修复（2026-08-23 第三次实测）

实测发现答案页调用输出 177855 字符被截断后**续写卡死**：

| 问题 | 根因 | 修复 |
