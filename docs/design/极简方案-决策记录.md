## 一、背景与目标

现状链路存在两层问题：

1. **同质化**：研读结果按卡片缓存复用（日志实证 `[复位·预研读复用] 缓存命中 → 跳过研读轮 → 9 批记录直接携带`），同一份教材多次生成时写作起点完全相同。
2. **冗余**：研读轮"写笔记 + 校验 + 缓存 + 前缀"这一整层，其产出（覆盖点名 + 摘要）中，**覆盖点名本就来自程序侧锚清单**，摘要则引入前缀膨胀与额外调用。

拟调整方向（待逐条敲定后定稿）：**删除研读轮**，写作期前缀只放锚清单点名，写作期**强制按覆盖点 browse** 取绑定片段，引用约束仍按资料类型分流。

## 四、逐条决议

### A1 锚粒度（学科差异） ✅ 已定

**问题**：锚取"第二层 coreKnowledge"这一取层口径是全学科统一的（已核实），但**该层的粒度**可能因学科而异，导致锚清单质量不齐。

**证据**：

- 英语有明确层位约束：`useAiGenerator.js:3162` "每个词条（英文+中文释义）独立标注为 **specificConcept**" → 词条下沉第三层，锚不膨胀。

- 语文**未指明层位**：`:3135` "每个生字独立标注（如"人""口""手"），绝不合并"、`:3145` "如'生字5个'→必须拆成5条独立知识点" → 若模型把生字放进 coreKnowledge，则"人/口/手"各成一锚，锚数量爆炸。

- 数学 `:3149-3157` 粒度中等（概念/公式/例题/几何性质），相对可控。

**风险**：锚过细 → 强制按点 browse 变成"逐生字取片段"，调用爆炸、写作碎片化；锚过粗 → 漏考点。

**候选解法**：

1. **补层位约束（治本）**：在分析提示词中明确三层语义——`bigConcept` = 单元/主题级；`coreKnowledge` = **可独立成题/可独立教学组织的考点**（锚取此层）；`specificConcepts` = **最小单位**（生字、词条、符号、数值等一律下沉）。并对"最小单位易上浮"的学科（语文生字、英语词条、化学式等）显式声明。
2. **先取证（验收）**：加"锚粒度诊断"日志——按学科/章统计 coreKnowledge 条目数、每锚平均字数、specificConcepts 条数；跑语文低段 vs 英语单元对照。
3. 1 + 2 组合：先补约束（治本），再用诊断验证收敛。

**结论（2026-09-11 用户拍板）**：在**教材分析阶段**把输出结构直接定义为**锚树固定结构**——分析产出的那一刻，结构本身就是锚清单，取锚成为零解释的直接读取。

**1. 固定结构（分析输出即锚清单本体）**

```
knowledgeHierarchy: [                    ← 锚树本体
  { bigConcept: 单元/主题级,               ← 第1层：仅作归属分组，【不取为锚】
    coreKnowledge: [                      ← 第2层：锚清单本体，【每条 = 一个锚】
      { name, level, specificConcepts[] } ] } ]
```

取锚 = `flattenAnchorTree` 直接读第2层，无解释余量。

**2. 粒度判据（写死在结构定义内，全学科统一）**

- 第2层条目 = **可独立成题 / 可独立教学组织的考点**（锚的定义）

- **最小单位强制下沉第3层**：单个字、单个词条、单个符号、单个数值、术语碎片

- 反例自检：第2层出现"人/口/手"式单字名 → 违规，须下沉

- 学科分支只决定"提取哪些要点形态"，**不改层角色、不改粒度判据**；英语既有"词条 = specificConcept"提升为**全学科通用判据**

- 按既有红线：用语义判据，不写数字区间

**3. 入库固定结构（用户强调）**

重分析结果的解析入库须按锚树契约校验；结构不符 → 不落库（重试/报错），确保**存储即锚清单**。

**4. 迁移策略 B2'（本次）**

- 用**现有逐章"分析提取"入口**重新分析全部已分析章节（不新建批量入口）

- 验收：锚粒度诊断（每章锚数 / 短锚占比(名长≤3字) / specificConcepts 条数分布 / 绑定状态分布），覆盖全部已分析章节，确认收敛

- 将来标准若再变，再考虑 B1'（标准段哈希机制）；本次不建机制

**影响面**：教材分析提示词（schema 段 + 提取规范段 + 学科分支）+ 解析入库校验 + 诊断日志。不动锚取层逻辑与下游。

**补充：会不会影响模型对内容的分析？——不影响"分析什么"，只影响"放到哪一层"**

- 学科分支的**提取规则原样保留**（该学科有哪些要点形态）→ 模型提取的信息范围不变；被下沉的条目（生字/词条等）**照样被提取**，只是从第2层移到第3层，信息量不减。

- 需**双向盯防**（诊断必须三个指标一起看，单看锚数会被"为满足结构而凑层"骗过）：

| 风险 | 表现                          | 后果                 |
| -- | --------------------------- | ------------------ |
| 过细 | 单字/词条上浮第2层                  | 锚爆炸、逐点 browse 调用爆炸 |
| 过粗 | 判据过严（如"必须能独立成题"）把本该做锚的考点也下沉 | 锚太少、漏考点            |

- 两个防呆：判据用**语义判据 + 反例**（不写数字区间，防诱导删减）；入库校验**只判结构、不改内容**（防"削足适履"删已提取内容）。

### A2 强制 browse 力度 × 五档覆盖契约 ✅ 已定

**问题**：现状五档契约只驱动两件事——browse 引用约束（`useAiGenerator.js:4209`，`mode==='full'` → 可引用，其余 → 参考-only）、防照搬守门（`:5261`，`mode!=='full'` 开启）；对账相关用法已随对账废除成死代码。极简方案中，契约需**新增驱动"强制浏览力度"**。

**结论（2026-09-11 用户拍板，采方案甲）**：**点名清单统一 = 全部合格锚**（排除 `bind.status === 'missing'` 与 `isExtension`），**契约只负责"强制力度 + 引用约束"**，不再分叉点名来源——保证点名口径唯一、可解释。

| 模式              | 类型                               | 强制 browse 力度 | 引用约束     |
| --------------- | -------------------------------- | ------------ | -------- |
| full            | summary/preview/dictation/review | 逐点必取         | 可引用/归纳原文 |
| per-lesson-full | practice                         | 按课逐点必取       | 参考-only  |
| focus           | special/reading                  | 仅对领域/主题相关点强制 | 参考-only  |
| sampled         | exam                             | 不逐点强制        | 参考-only  |
| none            | errorbook                        | 不强制          | 参考-only  |

**focus 的领域点来源**：`specialDomains.js` 领域注册库的**课标语义锚**（用户选领域 → 领域锚 + 可选栏目），不是"从教材锚里筛主题点"。

**sampled（考卷）细则**：点名 = 全部合格锚，作为**可命题范围声明**（非"必须全覆盖清单"）；不强制逐点浏览、允许未覆盖。

**名词澄清**：点名 = **可命题范围**，不是"必须全覆盖清单"；覆盖要求由"强制力度 + 委托书措辞"承载，不由点名承载。

**影响面**：`coverageContract` 用途扩展（新增驱动强制力度）；写作期强制流程与 browse 调用编排；`specialDomains.js` 定位不变（focus 的领域点来源）。

### A3 防"没读就写" + 强制的实现形态 🔶 待定

**事实澄清**：现状研读只校验"**笔记引用可溯源**"（`studyRound.js:isQuoteTraceable`），**不校验正文是否基于素材**。因此删研读**不新增**"没读就写"的风险——该风险现状即存在。

**强制的两种实现形态**：

| <br /> | I1 程序注入                     | I2 模型取 + 程序校验                  |
| ------ | --------------------------- | ------------------------------ |
| 做法     | 程序按点取该点绑定片段、注入该点的写作请求       | 模型自行调 browse，程序核对"该点已取过"才推进/采纳 |
| 保证     | 模型**无跳过机会**（结构性保证）          | 靠校验兜底，模型有自主空间                  |
| 与既有原则  | 与研读轮"程序组织材料消息"同一机制（去掉笔记）    | 与"素材唯一途径 = browse"一致           |
| 代价     | 失去"该点素材不需要"的判断（但这正是"强制"的定义） | 模型可能取错/漏取                      |

**候选落地方案**：按 A2 力度表分派（full / per-lesson-full / focus 领域点 → I1；sampled / none → I2），或**单路径参数化**（一套"逐点循环取片段→写该点"编排 + 一个"必取/可跳过"开关，语义等同混用但只有一条代码路径）。

**混用的利弊**：

- 利：与力度表对齐；资源与风险匹配；不让"不需要覆盖"的类型白花取料成本。

- 弊：两条代码路径（维护/回归翻倍）；可解释性负担；模式与实现耦合；focus 一条资料内两种形态混用最复杂。

- 单路径参数化可消解"弊"的前三条。

**结论（2026-09-11 用户拍板）**：实现形态 = **单路径参数化 + 全部差异静态查表**。

- 编排**只有一条路径**：`逐点循环 { 取该点绑定片段 → 写该点正文 }`

- 差异全部在**编排前**查表求出，写作期**零判断、零分支**：

| 决定             | 查哪里                                                           | 时机  |
| -------------- | ------------------------------------------------------------- | --- |
| 是否强制逐点（必取/可跳过） | A2 契约表（`genType → mode`）                                      | 编排前 |
| focus 的必取点集合   | `specialDomains`（**学科 × 学段** → 领域锚，`stageList` 五档直列）+ 勾选范围合格锚 | 编排前 |
| 引用约束           | A2 契约（`mode === 'full'`）                                      | 编排前 |

- focus 语义落地：**必取 = 领域锚**（来自领域注册库）、**可跳过 = 教材锚**；由查库 + 查表得出，不是运行时判断。

- 由此消解"混用"的前三条弊（两条路径、可解释性、模式与实现耦合），保留其利（与力度表对齐、资源与风险匹配）。

**增强项（本次不做，记录待议）**：正文与该点绑定语料的"术语/数据一致性检测"（抓"读了素材却凭记忆写"）——属新能力，建议单独立项。

**验收断言（实施后须可观测）**：

1. 编排循环内**不含按资料类型的条件分支**（差异均在编排前一次性求出）。
2. 点名清单 = 全部合格锚（排除 `missing` / `isExtension`）。
3. 强制力度与引用约束均由 A2 契约表驱动，不散落硬编码。
4. focus 的必取点集合可由"学科×学段"查 `specialDomains` 稳定复现。

### A11 段类型过滤口径 ✅ 已定

**问题**：`isReturnableSegment`（`generationSession.js:205-209`）只排除 5 个标签（练习/作业/习题/practice/exercise），但 `if (!t) return false` 使**空/未标注 type 的段也被过滤**；且练习段被整体排除在研读材料与防搬抄语料之外。

**结论（2026-09-11 用户拍板）**：**不再过滤练习段**——过滤会使教材不完整；练习段含题型/难度参考价值，原则是**防搬抄，而不是丢弃参考**。

**必须三处联动（否则不一致）**：`isReturnableSegment` 现用于 ① 研读材料供料 ② browse 返回片段 ③ 防搬抄比对语料（`copyGuard.refCorpus`）。练习段改为"提供"后，**③ 必须同步纳入比对**，否则"练习段照搬"无法被抓到。

**配套**：委托书补一条约束——练习段仅供理解题型与难度，不得照搬题目。

**附带核查项**：确认 Step1 的段类型标注覆盖率，避免"空 type 被静默过滤"造成丢料。

**验收断言**：① 同一份教材，研读材料与 browse 返回中练习段可出现；② 正文照搬练习段时 `copyGuard` 能命中；③ 空 type 段的处理方式明确（不再静默丢弃）。

### A10 绑定片段去重 🔶 待定

**问题**：多个锚落 `chapter` 兜底时，各自取"章内关键段前 3 段"（`coverageAnchor.js:108`）→ **同一批段被重复贴 N 次** → 研读材料虚高。疑似解释"单元 9 批 / 材料上限约 2 万字 vs 原文 5872 字"的异常。

**能否在分析层解决**：**只能部分**。A1 的粒度规范会提高命中率、减少落兜底数量；但语文的教学概念（"生字认读""词语理解"）本质不出现在课文文字里（`useAiGenerator.js:785-786` 注释已言明），兜底无法消除 → **绑定层去重必须做**。

**候选解法**：跨锚保序首次出现——同一段只贴一次（保留首次出现位置）。

**结论（2026-09-11 用户拍板）**：**本次做**。绑定层跨锚去重——同一段只贴一次（保序保留首次出现位置）。

**分工**：分析层规范（A1）负责**减少**落兜底；绑定层去重负责**兜住剩余**（语文教学概念无法字面命中，兜底不可消除）。

### A4 上下文上限 / 写作形态 🔶 待定

**已核实事实**：

- 代码只有**输出上限**钳制（`resolveEngineOutputLimit`），**输入上下文窗口无任何管理**；`estimateTokens` 仅用于引擎选型与预算估算。

- 工具调用的"浏览"必然使片段留在上下文，且因每轮重发全文而**成本放大**（长度 × 剩余轮数）。

- 让原文不留在"写作期"上下文，只有两条路：**压缩**（原文在研读阶段消耗）或**分片**（跨片不累积）。

**业界主流四模式（含已知缺陷）**：Stuff（装得下时最连贯，超窗即溢出）；Map-Reduce（分片各自摘要再归并；归并步骤自身可能超窗需递归折叠，"摘要的摘要"丢失跨片关联）；Refine（逐片更新已有结果，串行慢、后期片权重过大）；层级归并（>100K token 适用，递归归并**放大幻觉**）。共识：**把上下文当有限资源做预算分配**（系统提示 / 检索内容 / 输出预留）。

**对照本项目的短板**：① 研读只有 Map、**没有 Reduce**——批次笔记并列堆叠，跨批关联丢失；② 输入侧**完全没有预算管理**。

**待定方向**：

- 输出侧保持 Stuff（一气呵成）+ 截断续写

- 输入侧把研读升级为"**有界压缩 + 归并**"，使笔记量有界且连贯

- 补"上下文预算管理"：输入预算 = 窗口 − 输出预留 − 固定部分；超预算触发压缩/裁剪并**如实报告**

- 批预算 2500 字/批过小（整册 ≈ 80 批调用），需按上下文窗放大——**前提先确认引擎上下文窗口**

**引擎窗口事实（2026-09-11 联网核实·官方文档）**：deepseek-flash / deepseek-v4-pro **上下文 1M tokens、最大输出 384K tokens**（`max_tokens` 取值 1~~384K，输入+输出受上下文限制）；旧 deepseek-chat/reasoner（V3.2）为 128K/4K~~64K。

**🔴 重要纠偏**：此前"整册必然撞窗、必须分片"的结论**作废**——在 V4 的 1M 窗口下，整册材料可一次装入，**输入侧不是瓶颈**；真正的约束转移到**输出侧**（应用护栏 64K tokens）与**长输出完整性**。

**结论（2026-09-11 用户拍板 + 更正）**：采用 **Map → Reduce → Stuff 三段工作流**，**所有参数一律自适应，不设固定常数**。

**🔴 压缩的语义更正（关键，与旧研读本质不同）**：

- **压缩对象 = 全部教材原文**（保真压缩：保留原文自身的内容、顺序与结构），**不是**按覆盖点写"理解+引用"的笔记

- **写作期输入 = 锚点清单 + 压缩后的原文 + 委托书**（三件）

- 这样做的根本好处：压缩文本与原文**同构**，不会像旧研读笔记那样引入"覆盖点/批"这套**第二组织**——正是 A12 漏栏的机制 B 来源

```
③-a Map    分批压缩原文（批预算自适应）
③-b Reduce 归并成一份连贯、有界、保真的压缩原文（超窗则递归折叠）
④  Stuff   一次成文：锚点清单 + 压缩原文 + 委托书 → 单次输出全文（一气呵成）
```

**压缩程度与验收（2026-09-11 用户定稿）**：

- **大范围可显著压缩**——压缩比不设固定值，自适应

- **底线 = 锚点与压缩文本能"对应到"**（对应得上即通过）；**不做逐点反查支撑**（用户判断：反查没有支点、不精准、无意义）

- **防"假原文压缩"（关键）**：压缩的**输入必须是纯教材原文**；**锚点不得混入压缩文本、更不得被当作素材改写**——否则产出的是"锚点清单的复述"（假压缩）且与锚点清单重复。锚点只在"清单"里出现一次。

- 压缩须**保留原文结构与关键事实**（不得删栏目、不得改写事实）

- **压缩比按契约模式分流**（2026-09-11 用户确认）：`mode === 'full'`（知识型，含**默写**/知识梳理/复习）须**保留原文表述与原句**——默写答案即原文原句，压掉就是错答案；命题型（practice/special/reading/exam）题干与情境自拟，**可大压缩**

**写作期输入顺序（用户方案：锚点清单 → 压缩原文 → 委托书）**：

- 依据 LLM 的**首尾强、中段弱**特性：委托书（最高优先级指令）置**末尾**锚定 ✓；锚点清单（覆盖范围声明）置**开头**，让模型"带清单读素材"、利于锚点↔素材对应 ✓；压缩原文（素材，非指令）置**中段** ✓

- **风险与缓解**：中段易被忽略（lost in the middle，与 A12 漏中间栏目同源）→ 压缩文本**按原文结构分节保留小标题**，便于定位、抗中段遗忘

- 可选极短指针（非重复）：委托书内加一句"覆盖范围以开头锚点清单为准、素材以中段压缩原文为准"——仅作指针，不复述清单内容

**分批与拼接（用户认可）**：Map 分批按**章/节（自然边界）切分；Reduce 按**原顺序拼接（不产生新的组织），拼接处无缝。

**验收断言（定稿）**：① 锚点与压缩文本可对应；② 压缩文本保留栏目/章结构；③ 压缩文本内**不含锚点清单式条目**（防假压缩与重复）；④ 写作期输入顺序为"锚点清单 → 压缩原文 → 委托书"；⑤ 压缩输入为纯原文（锚点不参与压缩生成）。

**参数自适应原则（用户定调：参数类都自适应，不硬编码）**：

- 建**引擎能力表**（provider/model → 上下文窗、最大输出），参数由"能力表 + 实际输入量"推导，不散落常量。

- **输出护栏自适应**：取 `min(模型最大输出, 上下文窗 − 输入预算)`，替代固定 64K。

- **批预算**：按阅读质量自适应（不被窗口逼小），**不按学段/学科各配一套数字**。

- **批数 = 材料量 / 批预算**，天然适配学段/学科差异；批数多时用**并发**压缩总耗时。

- **学科×学段材料量诊断**（并入 A1 诊断）用于验证参数是否合理。

**验收断言**：① 整册材料可被完整读入（无静默截断/丢批）；② Reduce 产出有界且连贯的总账（跨批关联保留）；③ 写作仍为单次成文；④ 所有预算由能力表推导，代码内无新增固定魔数。

### 5.3 实施对账规程（专防"缺胳膊少腿"）

用户多次强调：**打磨多轮定下的方案，实施必须精准、不得缺项**。据此定六条：

1. **实施前**：列出本次要落地的**断言编号清单**，逐条写明"改哪个文件、怎么验"——先有计划再动手。
2. **一次实施只覆盖一条决议**（或一组强关联断言），禁止混做；混做会让漏项藏进大改动里。
3. **提交前逐条核对断言**，每条必须给出**证据**：自动化测试名 > 可观测日志样例 > 人工核对项（人工项须显式标注"人工"）。
4. **提交信息必须引用决议编号与断言编号**（如 `A4-3/A4-5`），便于回溯。
5. **提交后回填本台账**：状态 + 证据 + 提交号；**无证据的断言保持"待实施"**。
6. **偏差先改记录**：实施中若发现某条不可行/需调整，先把该条退回 🔶 并写明原因与替代方案，禁止静默偏离后直接提交。

### 5.4 状态同步规则

- 决议转 ✅ 仅代表"**讨论定稿**"；**代码落地的唯一凭据是台账里对应断言的证据**，两者不得混为一谈。

- "决议已定、尚未实施"须显式标注**待实施**，不得默认视为完成。

- 实施完成后回填"实施提交号"，便于回溯"哪条决议由哪个提交落地"。
