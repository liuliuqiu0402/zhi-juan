## 六、源头责任划分（用户裁定 2026-09-30：**模型侧必须做到位，不依赖程序侧检查与兜底**）

> 用户原话："我们的原则是，**源头模型侧必须做到位的，不要去依赖程序侧的检查和兜底**。必须对源头模型侧有
> 高质量要求。要不然总是惰性，以为有程序侧。"

**责任判据（一件事该谁做）**

| 类别 | 归谁 | 理由 | 例 |
| --- | --- | --- | --- |
| 内容/形态/自洽/质量（"写成什么"） | **模型侧** | 模型能表达、可判定；程序替代＝放松要求 | 加点标记、作答位形态与位置、空数×分值账目、声明↔实给、情境与标题命名口径 |
| 渲染实现/格式契约（"怎么呈现"） | **程序侧** | 模型无法表达（无 DOM/CSS/OMML 能力） | 大类层居中、格子/横线载体渲染、OMML 公式、页边距与分页 |
| 生成机制（长度/续写） | **程序侧** | 引擎输出上限所致，非内容判断 | 截断续写链、缺号重试、预算升级 |

**按此重排现有"程序侧补偿"清单**

| 现有程序侧动作 | 判定 | 处置 |
| --- | --- | --- |
| `answer-area-fix` 作答区补差 | 越界（内容质量） | **模型侧条款已在岗**；程序侧**降级为最后一道兜底**并留痕（问题列表），不得作为"要求可放松"的理由 |
| 载体补差（田字格/横线，2j-4/2j-5b） | 越界 | 同上（模型侧载体协议已单源在岗） |
| 作文格补全（格数按学段 × 分值换算） | **渲染实现** | 保留（格数换算是程序能力） |
| `normalizeMathCircleBlanks` 结果位方框剥离 | 越界 | 归兜底；模型侧已有"结果位不配方框"条款 |
| `emphasisFormFix`（内容型 `<u>`→`<strong>`） | 越界 | 归兜底；模型侧强调口径已按类型分叉在岗 |
| `wrapBareBlankRuns`（em/全角空格 → 载体） | **渲染实现** | 保留（把空白变成可渲染横线，模型写不出 class 档位） |
| 截断续写链 / 缺号重试 | **生成机制** | 保留 |
| 各类探针（只报不改） | 可见性 | 按裁定降级：**不再当质量保障**，只作漏网可见 |
| **大类层居中**（本节新做，D2） | **渲染实现** | 已做：`markExamBigCategory` 打标 + 行内 `text-align:center`（预览/HTML/PDF/DOCX 四处同口径）；**加粗由模型侧负责，程序不代劳** |
| **卷首结构兜底**（本节新做） | **结构性保险** | 已做：`normalizeExamHeadOrder`——只**重排已存在的结构件**（时间行移到 `<h1>` 之后），**缺件不补、不造**；源头条款"卷首固定顺序"在模型侧（单源） |

**程序侧补差是否造成"双重注入/两套指令打架"？**（2026-09-30 用户提问，逐项核证）

**结论：不存在双重注入。** 程序侧补差（`answer-area-fix`、载体补差、`normalizeMathCircleBlanks`、`emphasisFormFix`、作文格补格）
**一个字都不进提示词**——它们只作用于**生成后的 DOM/导出文本**；进实发文本的"由系统…"句只有四类，全是渲染/生成机制说明
（主标题由系统程序拼装、页码分页由系统生成、答案页由系统单独调用、配图与竖式书写区由系统按渲染契约注入）。

| 真实风险 | 性质 | 处置 |
| --- | --- | --- |
| **惰性**（"反正程序会补"） | 主要风险：错误被静默掩盖 → 同一问题反复出现 | 源头侧要求**不放松**；兜底**必须留痕**（问题列表可见），不得反噬要求 |
| **判据不同源** | 唯一可能真打架之处 | 逐项核证：`answer-area-fix` 读 `getAnswerRegion(subject, stage)`（`ANSWER_REGION`）与提示词侧规格**读同一张表**、上限同源 `ANSWER_MAX_ROWS_BY_STAGE`；`normalizeMathCircleBlanks` 与规格层算式填空条**同语义**；`emphasisFormFix` 与强调口径分叉条一致 → **判据同源，不打架** |
| **"由系统…"措辞被读成"不用我管"** | 语义风险 | 措辞指明"系统做什么"，同时明确"正文不得改动/不得另写"（该模型做的部分仍写明） |

**结论**：程序侧今后只承担三类——**渲染实现、生成机制、有限兜底（必须留痕且不得反噬要求）**；
凡"本应由模型做到位"的，一律**先补强模型侧要求**，程序侧兜底只是最后一道。
