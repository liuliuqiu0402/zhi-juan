# 修复准则 · 检查清单（每次改动前逐条过）

> 用途：本文件是**本仓库一切修改的验收标准**。改代码/条款/规格/文档前，逐条对照；能机械校验的见
> `tests/config/fixChecklistGuards.test.js`（守卫转红即为违反）；**单一实现**（判据正则只许一份）见
> `tests/utils/singleImplGuards.test.js`（扫源码断言字面量全模块只出现一次）。
> 来历：这些要求由用户在多轮评审中提出，**不得依赖用户再次提醒**。

## 一、动手前（必须先做，不得跳）

1. **先看全局，再决定改什么**：按"层"清点该概念的**全部生产方与消费方**（生成/指令层、程序校验清洗层、渲染/导出/排版层、规格库 UI、测试、文档），而不是顺着症状找一处。
2. **已修过的地方要复核**：同一口径（答案区、分条、载体探针、题号边界…）是否**全通道接入**；有漏点先补全。
3. **评估涉及面 × 牵扯面并据此排序**：牵扯面大且**无法自证**的（尤其影响导出/预览观感的），后置到有真机验证时再做，不拿未验证的观感冒险。
4. **决策自己定**：按本清单与既定原则裁定，不把技术决策推回给用户。

## 二、改什么（原则）

5. **规格库（单一事实源）为源，各端皆消费方**：同一事实只许一处定义；发现"库里有、某端自己写死或被旁路"，一律改成读库。
6. **不得有第二副本静默漂移**：确有副本（如渲染静态尺寸）必须加**等值守卫**钉住。
7. **模型侧为主、程序侧为辅**：能从**注入条款**解决的，不靠程序事后删/改/截断内容去补。
8. **学段 × 学科特性，禁止一刀切**：有差异的必须门控；适用范围**由规格表推导**（如 `WRITING_CARRIER` 允许表），不靠硬编码学科名列表。
9. **无指向性诱导**：条款只用**形态/规格词**描述（不点题型名去暗示答案、不给示例把模型带向特定结果）。
10. **载体自洽 + 内容自洽**：输出的作答载体符合规范且前后一致；生成内容内部自洽（题干↔答案↔分值↔题号）。
11. **根治不打补丁**：不加兼容 shim、不留死码；除"按学段/学科的正当门控"外不加特例。
12. **不擅自删内容**：内容类问题走模型侧；确需程序动内容的，先取得明确同意。

## 三、动手后（收尾）

13. **注释/文档同步改准**；文档里"事实源"指向的**文件必须真实持有该定义**（不得指向只是名单/不存在的文件）。
14. **带回归**：新增或改准用例，**断言读规格库、不写死数值**。
15. **能机械校验的一律做成守卫**（防回潮）。
16. **全量测试通过**才提交；提交信息写清"根因/改法/证据"。
17. **临时文件清理**、工作区干净、提交推送（网络失败如实说明）。

## 四、本仓库已知的"易漏点"（历史踩坑，优先自查）

- 规格库新增键**必须同时进 `getMergedSpec` 合并白名单 + `LAYOUT_SPEC_DEFAULTS` + `LAYOUT_SPEC_GROUPS`**，否则"面板可调、读取端拿不到"= 死字段。
- 区域/口径类判据（答案区边界、题干内分条、载体存在性探针、题号边界）**必须全通道接入同一单源**；只接一半＝留着同类缺陷。
- 规格库"学科无关"的宣称要经得起追问：**篇幅由答案长度决定的题**（书面表达、多步解答）不能与"卷面空间"共用一个上限。
- 新增条款要检查**是否与该学科已有条款相抵**（例如"同题只给一处作答位" vs 数学"竖式过程区"）。

## 五、已后置（待真机验证，按"三、动手后"第 3 条）

  按准则"牵扯面大且无法自证的，后置到有真机验证时再做，不拿未验证的观感冒险"，**留到真机跑样时一并处理**。

## 七、真机跑测核对项（跑实样时对着打勾）

> 程序侧能自证的已由测试覆盖；本节只列**只能在真机（导出件 Word/WPS ＋ 预览）上确认**的项。
> 记一条纪律：**只许先确认、不顺手改渲染**——改渲染/导出按准则第 3 条，与真机确认同批做。

### A. 本轮模型侧条款改动的验证点（2026-09-29）
- [ ] 英语**低段**书写题是否真的输出四线三格，且未被当"越界"剥离
- [ ] 语文低段 抄写/听写/默写 类：书写格是否紧贴其对应书写对象（原条款只对"看拼音写词语"成立）
- [ ] 数学竖式题：等号后得数结果位 与 过程书写区 是否**并存**
- [ ] 题干内短答空位 ＋ 题后成段书写区 是否**并存**（不再被判"混用"而丢掉长答载体）
- [ ] 数学低段结果位：是否允许「＝＿＿＿」/「＝（　）」定位
- [ ] 英语高中成篇表达：行数是否给足（不再被 8 行顶住）

### B. 老回归点（每轮都看）
- [ ] 每道大题**最后一小题**的书写格是否还在（曾因 `|| null` 边界走到文末被误剥）
- [ ] 答案区逐题对应（题号同号、无缺题、无错位）
- [ ] 作文格落点在整题题干之后、分条之后；横线与格子不并存
- [ ] 同题**同性质**只一处作答位（括号空位 ＋ 横线 不重复载体）

### C. 渲染/导出端（本轮**只读**审计已做；此处只看观感，不动代码）
- [ ] 预览 / 编辑器 / 导出 三端：四线三格·拼音格行高是否一致（行高在三处各写一份，已加**等值守卫**）
- [ ] 田字格·米字格尺寸三端一致（规格库 `GRID_CELL` 为源；导出端按 primary 档统一）
- [ ] 空位最大档（`blank-N`）CSS 与导出端一致（规格库 `BLANK.maxBlank` 为源，两处兜底同值）
- [ ] 作文格：格数/步进/默认跨度三端一致（规格库 `ZUOWEN_*` 为源）

### D. 口径决策：作答区行数上限该给谁更大空间（真机看过再定，不在代码里编数）

需求行数 = min(分值 × 系数, 学段上限)。下表为"**会撞上限**"的分值阈值（系数×上限取自
规格库 `ANSWER_REGION` 与学段上限表）：

| 学科 | 小学低段 | 小学中段 | 小学高段 | 初中 | 高中 |
| --- | --- | --- | --- | --- | --- |
| 默认（数学/理化生/政史地/道法等） | 1.4 / 4 → **>2.9 分** | 1.2 / 5 → >4.2 | 1.0 / 6 → >6 | 0.9 / 8 → >8.9 | 0.8 / 8 → **>10 分** |
| 语文 | 0.5 / 4 → >8 | 1.2 / 5 → >4.2 | 1.0 / 6 → >6 | 0.9 / 8 → >8.9 | 0.8 / 8 → >10 |
| 英语 / 科学 | 1.4 / 4 → >2.9 | 1.2 / 5 → >4.2 | 1.0 / 6 → >6 | 0.9 / 8 → >8.9 | 0.8 / 8 → >10 |

**结论（待定范围，非判决）**：被上限**系统性压住**的是"单题分值高、且答案篇幅由内容本身决定"的两类——
成篇/成段表达（英语初/高常见 15–25 分，远超阈值 8.9/10）与多步推演解答（数学/理化初/高常见 10–12 分）。
小学中高段 6 分以上长答同样越限，但小学长答多为"几句话"，按卷面惯例压缩合理，**倾向不动**。
