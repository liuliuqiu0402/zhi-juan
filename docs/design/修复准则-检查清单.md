# 修复准则 · 检查清单（每次改动前逐条过）

> 用途：本文件是**本仓库一切修改的验收标准**。改代码/条款/规格/文档前，逐条对照；能机械校验的见
> `tests/config/fixChecklistGuards.test.js`（守卫转红即为违反）；**单一实现**（判据正则只许一份）见
> `tests/utils/singleImplGuards.test.js`（扫源码断言字面量全模块只出现一次）。
> 来历：这些要求由用户在多轮评审中提出，**不得依赖用户再次提醒**。

## 一、动手前（必须先做，不得跳）

1. **先看全局，再决定改什么**：按"层"清点该概念的**全部生产方与消费方**（生成/指令层、程序校验清洗层、渲染/导出/排版层、规格库 UI、测试、文档），而不是顺着症状找一处。
2. **已修过的地方要复核**：同一口径（答案区、分条、载体探针、题号边界…）是否**全通道接入**；有漏点先补全。
3. **评估涉及面 × 牵扯面并据此排序**：牵扯面大且**无法自证**的（尤其影响导出/预览观感的），后置到有真机验证时再做，不拿未验证的观感冒险。
4. **决策自己定**：按本清单与既定原则裁定，不把技术决策推回给用户。

## 二、改什么（原则）

5. **规格库（单一事实源）为源，各端皆消费方**：同一事实只许一处定义；发现"库里有、某端自己写死或被旁路"，一律改成读库。
6. **不得有第二副本静默漂移**：确有副本（如渲染静态尺寸）必须加**等值守卫**钉住。
7. **模型侧为主、程序侧为辅**：能从**注入条款**解决的，不靠程序事后删/改/截断内容去补。
8. **学段 × 学科特性，禁止一刀切**：有差异的必须门控；适用范围**由规格表推导**（如 `WRITING_CARRIER` 允许表），不靠硬编码学科名列表。
9. **无指向性诱导**：条款只用**形态/规格词**描述（不点题型名去暗示答案、不给示例把模型带向特定结果）。
10. **载体自洽 + 内容自洽**：输出的作答载体符合规范且前后一致；生成内容内部自洽（题干↔答案↔分值↔题号）。
11. **根治不打补丁**：不加兼容 shim、不留死码；除"按学段/学科的正当门控"外不加特例。
12. **不擅自删内容**：内容类问题走模型侧；确需程序动内容的，先取得明确同意。

## 三、动手后（收尾）

13. **注释/文档同步改准**；文档里"事实源"指向的**文件必须真实持有该定义**（不得指向只是名单/不存在的文件）。
14. **带回归**：新增或改准用例，**断言读规格库、不写死数值**。
15. **能机械校验的一律做成守卫**（防回潮）。
16. **全量测试通过**才提交；提交信息写清"根因/改法/证据"。
17. **临时文件清理**、工作区干净、提交推送（网络失败如实说明）。

## 八、实样复盘：全局根因（2026-09-29 二年级语文·阅读综合检测）

> 用户要求"不能只盯个体，得找出全局的根因"。本节记录从该实样**解出的证据**与据此判定的**全局根因**
> （不是逐条打补丁）。

**证据（docx 内部结构解出，不是看外观猜的）**

- 全卷**只有 1 张表**（得分表）→ 田字格/拼音格/作文格**一个都没有**；`w:drawing` = 0。
- 作答位 = 43 处"下划线 + 空格串"；其空格数是**等差数列 8,8,12,16,20,…172**
  （= 导出端 `N*4`），即空位档位 N = **2,2,3,4,5,…43**——**N 跟着"第几个空位"走**，与答案长度无关。
- 程序侧各处宽度换算都是**按宽度**算的（`blankWidthForChars` / `clampBlankWidth` / `spaceBlankWidth`），
  全模块**没有**"按序号编号"的代码 → 递增来自**生成出来的 HTML 本身**（模型把 `blank-N` 的 N 当成了序号）。

**据此判定的四条全局根因**

| # | 根因 | 为什么是全局的 | 处置 |
| --- | --- | --- | --- |
| G1 | **`blank-N` 的 N 没有定义**：题类条款只给了标记 `blank-N` 却没说 N 是什么（内容型那条倒有说明）→ 模型把它当序号 | 影响**所有题类资料的所有空位**（不只这一份） | 已在题类"短答宽度换算"句补：**N＝该空答案的字位数，不是序号**，且严禁按题序递增/一律等宽 |
| G2 | **程序侧越权决定宽度**：导出端把 N 档乘 4（NBSP=0.5em → 2N em，比预览宽一倍）并设 8 个 NBSP 的地板 | 影响**全卷每一个空位**的观感 | 已改**逐档透传**（N em = 2N 个 NBSP，与预览同宽），并加守卫（该系数与 NBSP 口径同源） |
| G3 | **载体职责被切成多条通道、彼此互指**：作文格模型侧只写"另有专用书写载体"（假指针）、程序侧补格又以"已有任一作答载体即不补"为界 → 谁都不输出；书写格则因**没有优先级**被"短答空位形态统一"覆盖成横线 | 影响**所有写话/习作类、所有写字类** | 作文格改**真协议**（语文各学段给出标记，与程序侧补格同形）；位置行补**优先级**（书写格优先于短答空位形态统一句） |
| G4 | **内容自洽缺"题干不得泄漏答案"**：情境句把待写词语直接写了出来（5/6 小题）→ 题目失效 | 影响**所有"看拼音写词语/填空/默写"类** | 已补自洽⑰（题干与情境不得出现待作答内容；待选材料/词库例外） |

**仍未归因（需生成后的源码才能定，不能靠外观猜）**

- 该实样的**作文格缺失**还有一半没定性：程序侧 2j-5 实测**会**补格（用同结构复现过），所以要么那一稿的
  HTML 里根本没进这一层、要么导出丢了，需要**生成后的 HTML** 才能定。
- 同卷还有两处已观察到但未归因：**卷首 10 个连续空段**（空行泛滥）、**连线题被写成"左〔空〕右"**（未给连线结构）。

**本轮补的一层：全矩阵自动验收（不再依赖用户去测）**

- 用户裁定："不要依赖每一个都要用户去测试——那么多学科、那么多学段、那么多资料类型，用户怎么测？"
- 新增守卫 `tests/recipe/carrierProtocolCoverage.test.js`：**15 学科 × 5 学段 × 9 资料类型**全跑，不看措辞
  在不在，只看**载体协议是否自洽**——
  ① **不得广播**：注入文本里的载体标记必须属于该 学科×学段 的允许集；
  ② **协议完备（防假指针）**：规格库要求应有的载体，注入文本必须给出**可施工标记**（"只写'另有专用
     书写载体'却不给标记"这类空洞会被判红）；
  ③ **冲突必须有仲裁**：书写格与"短答空位形态统一"并存时必须同时有优先级声明。
- 附带查出（已记录、未改）：**不在实际开设矩阵内**的边缘组合（小学物理/高中科学/初中思想政治等，
  借用其它学段骨架）模板里**缺"长答载体句"**；在册组合均正常。本矩阵对"在册"硬判、对"借用"单列，
  不静默放过也不混判。

**为什么"全局修了很多，实际仍不尽人意"（本轮自省，写下来防再犯）**

1. **验收口径错位**：此前大量回归断言的是"某句话在不在"（锁措辞），**不是产物形态**。措辞在位的条款
   之间可以互相抵消（书写格 vs 短答空位统一、作文格 vs "已有载体即不补"）——全绿也照样漏出去。
   → 处置：新增全矩阵验收按"载体协议自洽"判，而非按措辞判。
2. **多条款并存缺仲裁机制**：注入体是**拼起来的**（自洽①-⑰ + 作答空间 + 载体协议 + …），
   彼此优先级只在少数处显式声明 → 模型选一条执行、另一条被违反，而程序侧看不到"条款冲突"。
   → 处置：冲突对必须带优先级声明，做成机械检查（本矩阵 ③）。
3. **职责边界没有单源清单**：谁负责输出哪个载体，散落在注释里 → "两处互指=谁都不做"的空洞（作文格即此）。
   → 处置：真协议必须给可施工标记（本矩阵 ②）。

> 6 类改法：二选一修正 / 换要素 / 不达标即自行修订 / 缺号即补、重启即改 / 发现即改 / 引到三域。
> 它们**语义同向、不互相否定**，所以不会立刻致错；代价在维护面（同一现象两处定性相反这类问题就是漏网例，
> 见下方"互斥指令"一行）。第 7、8 行原先连"在哪个通道"都没搞清（误以为在模板里，实为生成端另路追加）——

**其二·超长输入（原"关键块优先压缩"分支）**

- 触发条件：`estimatedTokens > maxInputTokens`，而 `maxInputTokens` 的口径**已按引擎分三支**
  （唯一出口 `src/config/apiConfig.js` 的 `resolveMaxInputTokens`，与输出侧 `resolveEngineOutputLimit` 对称）：
  · **deepseek** → 产品封顶 `maxInputTokensDeepseek`（默认 100000，不按 1M 放开）；
  · **ollama** → `0.7 × 输出预算`（本地显存/上下文口径，原样保留，未改）；
  · **其他云端**（volcano/alibaba/zhipu 等）→ `Infinity`（未固证不钳制）。
- 🔴 成本与实测依据（据此 **deepseek 支的数值不动**）：官方价 deepseek-flash（= V4.1-Flash，上下文 1M、输出上限 384K）
  输入缓存命中 0.02/0.04 元·百万、未命中 1/2 元、输出 4/8 元（空闲/高峰）。实测（真实代码拼 9 类型×3 学科×3 学段 = 81 组合，
  素材取直放上限量级）：命题型 **0.84 万~1.09 万** tokens、全文型 **3.48 万~3.80 万** tokens；答案页调用 0.9 万~4.0 万。
  → deepseek 的 100000 有 **2.6 倍余量**；把上限提到 1M 与既有成本裁定（"物理上限只作参考、产品口径封顶，理由费用不可控"）
  自相矛盾，且实测根本到不了、收益为零。输入费也不是成本主体（占单次约 10% 量级，输出单价是输入未命中价的 4 倍）。
- 🔴 改前行为的**两处危害**（都比"尾锚偏位"重）：
  ① 它认的素材段是"段头为 `【教材原文`/`【模板参考`/`【教材参考` 的整段"，而**素材段常把其后的指令吞进同一段**——
     分析任务 prompt 的形状就是 `【教材原文】\n<原文>\n\n请完成以下分析任务：…\n必须返回以下 JSON 格式：…` →
     逐句压缩会**连指令与输出格式要求一起吃掉**；也就是说"压缩"无法安全划界；
  ② 写作/答案类调用的素材块是【锚点清单】/【压缩原文】/【正文】，**不属该分类** → 进来只有"整体前置 + 超预算整体丢弃"
     两种效果、零收益，最坏会丢掉答案页的【正文】（与"正文一律全文送模型、绝不截断"的既有口径直接相抵）；
     且它与 `programAttach` 的段级兜底口径冲突：兜底判据是"该段在不在委托正文里"，而本分支在调用层、晚于该判定 →
     被丢掉的段**不会被兜底补回**。
- **第一步（已落地·零风险）**：把"顺序反转 / 整体丢段 / 写作路径其实不压缩素材"如实产出为**可观测告警**
  （notes → `promptShapeNotes` → `bodyPathNotes` → 生成报告【问题列表】），原先只 `console.warn`、用户侧不可见 = 静默。
- **第二步（已落地）**：把该分支抽为纯函数（可离线构造超长输入断言，不依赖真机），钉住行为特征 + 防"生成端再留第二份内联副本"。
- **第三步（已落地·按裁定）**：**收口为"只体检、不改文本"**——模块改名 `src/utils/promptOversize.js`、函数
  `inspectOverlongPrompt`；`text` **恒等于入参**（一个字符都不动），只产出可诊断告警（超了多少、有没有素材段、
  为何不压缩、建议减少勾选或改用锚清单通道）。理由：素材/指令边界不可靠划界（危害①），压缩能力对该分支是净负担；
  且素材体量**上游已有护栏**（`textbookCompression` 的材料分档 `shouldDirectInject` 阈值 = min(上下文窗×3%, 输出帽×25%)
  + Map→Reduce 折叠 `DEFAULT_FOLD_LIMIT_CHARS: 24000` 字符 ≈ 1.6 万 tokens），实测最坏提示词 ≈3.8 万 tokens。
  长度若确实超出模型上下文，**交由 API 显式报错**——与"宁可失败给行动建议，不给半截内容"同源。
  守卫：`tests/utils/promptOversize.test.js`（三种调用形状 text 逐字节不变 + 答案页正文不丢 + 分析任务指令/JSON 格式不被吃
  + 上限口径三支 + 与输出侧对称 + 旧实现痕迹不得回归）。
