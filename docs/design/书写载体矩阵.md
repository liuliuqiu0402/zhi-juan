**选择规则（题类）**：`buildAnswerSpaceInstruction`（学科×学段注入）
- 带**选项**的题：形态**一律圆括号空位**（禁用横线）；**位置按学科**——外语类在**题首**、中文科目在**题干末尾**；半角括号（✅ 已修 + 测试）。
- 所填为**符号**（字母/序号/√×）→ 括号空位或圈作答；**短答**（词/句/数）→ 横线空位。
- 长答（成句成段）→ `ANSWER_REGION` 按学科×学段定：`line`（整行横线）或 `blank-area`（无线留白）。
- 数学算式缺数 → 方框/圆圈；比较大小 → 圆圈。

## 六、编辑器手动插入载体（2026-09-30）

> 定位：书写载体除作文格外，允许**用户手动插入/替换**。手动产物**走在生成链路之外**，
> 不受 2j-5 系列（相邻性/插入位置）修正保护 → **必须自带正确形态**。
> 形态与长度的**单一事实源** = `src/utils/carrierInsert.js`（编辑器不另写一套）；编辑器侧只做接线。

**① 形态契约（行内 vs 块级，按取证写死）**

| 类 | 载体 | 形态 | 关键约束 |
|---|---|---|---|
| 行内 | 田/米/四线三/六线/拼音格 | `<span class="X">&emsp;</span>` **一格一元素** | **不得用 `<div>`**（块级会不能混排、导出成独立行居中） |
| 行内 | 横线空位 / 括号空位 | `<u class="blank-N">` / `<span class="blank-N">` | 同 class、**不同标签**，故拆两项 |
| 行内 | 数学填空方框 / 填空圈 / 口语交际框 | `span.square-box` / `span.math-circle-blank-18` / `span.oral-box` | 均为行内单元素 |
| 块级 | 整行横线 / 留白行 / 竖式格 / 方格纸 / 作图区 | `<p>`、`<div class=…>` | 本身即整块作答区，**不是**书写格 |

> 每个入目录的载体在导出端 `utils/docxBuilder.js` 必须有对应分支（守卫 `tests/utils/carrierExportContract.test.js`），
> 否则会造出"预览有、导出丢"。未取证者**不进目录**。

**② 同类择一（同族载体互斥）**

- 族判据的**单一事实源** = `carrierInsert.CARRIER_FAMILIES / CARRIER_FAMILY_OF`（编辑器经 `closestCarrierFamily` 消费）。
- 族：**格类**（田/米/四线三/六线/拼音）一处择一；**空位类**（横线空位 ↔ 括号空位）**同族可互转**
  （用户裁定：能把原括号换成横线）；**填空框类**（方框/圈）；整行横线、口语交际框各自成族。
- ⚠️ `blank-line`（整行横线，块级作答区）**不属**空位族 —— 故按 class **精确匹配**，不用 `[class*=blank-]`（会误吞）。
- 插入前把选区/光标处的**同族载体整体**纳入替换范围（`carrierFamilyRange`）→ 不留空壳、不并排同类。
  · 内联节点 DOM（田字格/米字格）的范围须两侧各外扩 1 才含节点自身；标记包裹 DOM（空位）两端即整体。

**③ 打乱连线题右列（手动，不判断答案）**

- 结构：`div.match-question > div.match-col×2 > div.match-item×N`（无专用节点，由通用 `divWrapper` 承载）。
- 编辑器工具栏按钮走**事务**（原生可撤销），**只重排右列顺序**，不判断/不记录答案——对错由人工肉眼核对。
- 生成侧另有**确定性**打乱（`contentCleaner.normalizeMatchQuestions`，同输入恒同输出、幂等）；两者互补：
  前者管模型产物，后者管编辑器内的人工调整。注入侧**不得**出现"连线右列打乱"之类措辞（载体归程序）。

**④ 规范为两列结构（手动，框选触发）**

- 适用：模型偶发把"连一连"写成**同行线性段落** `左项 <分隔位> 右项`——左|右相邻即答案，且导出端只认两列
  `match-question`（`utils/docxBuilder.js` 连线分支）。
- 用户框选后一键转换：**左列保序、右列打乱、去掉分隔位**；不可切分行（题干等）原样保留 → 可整题连题干一起框选。
- "可切分行"判据：该行**恰一个分隔位**且分隔位两侧各有文字。**连续可切分行成组，≥2 行才成题**（一组 → 一处 `match-question`；
  被不可切分行隔开则各自成组）。
- 🔴 **识别必须按"模型可能输出的多副样子"来写**（2026-09-30 实测踩坑），`src/components/RichTextEditor.vue` 的 `lineTokens` / `scanLine` 为单一事实源：

| # | 分隔位形态 | 置信度 | 备注 |
|---|---|---|---|
| ① | `blank-N` 标记（`<u>` / `<span>` 承载） | 高 | class 可能整体丢失 → 退化为裸 `<u>`（形态②） |
| ② | 带下划线的纯空白文本 | 高 | ①的兜底（class 丢失时） |
| ③ | ≥2 全角空格 `\u3000` / 不换行空格 `\u00a0` | 低 | **半角连续空格不可用**：HTML 空白折叠会把它压成单个空格（实测），故全角/NBSP 才是可靠形态 |
| ④ | ≥2 连续下划线 `____` | 低 | 逐字保留，不受折叠影响 |
| ⑤ | 空白括号 `（　）` / `（  ）` / `( )`（全半角皆可） | 低 | **常整行只是一个文本节点、分隔位藏在节点内部** |
| ⑥ | ≥2 连续破折号/连字符 `——` / `--` 与箭头 `→` | 低 | 连线语义明确 |

- 🔴 两个必须记牢的结构真相（否则"看不出来"）：
  1. **每组的分组游标必须跨段持有**。真实连线题**每行各成一段**（也允许同段用 `<br>` 分行）；若按段重置游标，每段只攒到 1 行，
     `≥2 行成题` 永不成立——现象就是提示里"3 行可切分"却"未识别到可规范的连线行"。
  2. **文本块可嵌套**（连线行常被包在 `<div>` 里）→ 须用 `doc.descendants` 递归收集，不能只扫顶层块。
- 🔴 精度闸门（防误转）：低置信度分隔位（③④⑤⑥）若**右侧以句末标点收尾（。！？；）**，更像"题干/填空句"而非连线项 → 不当连线行。
  高置信度（①②）不受此限。反例已加锁：填空题干含「（　　）」的连续两行不得被转成连线题。
- 🔴 **刻意不做关键词自动识别**（"连一连"等词判据属指向性诱导），故不扩展 `normalizeMatchQuestions`（其规则 4
  亦明确"普通段落不转"）；只做用户显式触发的形态转换。
- 未规范时不会被静默放过：`examValidator` 2j-2"连一连空壳"会检出"题干声明连线但作答位是填写位"并报抽检。
- 守卫：`tests/components/matchNormalize.test.ts`（含 6 种分隔位形态正例 + 3 类反例）。

**⑤ 行内格子的换行契约（导出侧）**

- 行内格子导出为三 run：零宽占位 + drawing（浮动 anchor，**零流宽**）+ pad 空格（`w:spacing` 撑 2.5em）。
  行内**唯一可断行处**就是 pad 空格。
- 🔴 pad run **不得带 `w:noBreak`**：带了会把连续格子粘成一个不可断整体 → **超出页边距也不换行**（用户实测）。
  去掉后 Word 在每个格子单元的 pad 处可断行；2.5em pad > 格宽 → 图形恒在自己的槽内、不越右边界。
- drawing run 仍**保留** `w:noBreak`（护住图形不与其 pad 分离、不在行尾被拆开）。
- 守卫：`tests/utils/tzgBrSkip.test.js`（pad run 无 noBreak + drawing run 有 noBreak）。
