## 〇、总览（一句话）

**教材分析 → 锚点清单 → 读取并压缩勾选章节原文 → 写作期输入「锚点清单 + 压缩原文 + 委托书」→ 一次成文；随后按资料类型走两次生成（正文 + 答案页）或一次生成。**

***

## 一、主链路

```
① 教材分析 → 锚树（固定结构，第 2 层 = 锚清单）                    [A1]
② 锚点清单：按章分组、章序与原文一致                                [A1]
③ 读取勾选章节的完整原文（程序直读，按章顺序，不做锚点取片段）        [A15]
④ 压缩原文：Map（按章/节分批保真压缩）→ Reduce（原顺序拼接）         [A4]
⑤ 写作期输入 = 锚点清单 + 压缩原文 + 委托书（顺序固定，见 4.1）       [A4]
⑥ 一次成文（Stuff）+ 截断续写兜底（既有机制）                        [A4]
⑦ 两次生成（正文一次 + 答案页一次）或 一次生成（既有机制，按类型）      [既有]
⑧ 交付前核对：栏目级完整性 + 题号连续性                              [A5/A12]
```

**链路极简点**：**取消 browse 机制**——原文不再是"模型按需逐点取片段"，而是"程序直接读整章原文再压缩"。由此**没有工具轮、没有上下文累积**。

## 二、逐环节确定细节

### 1. 锚点清单（A1 · ✅ 已定）

**1.1 固定结构（分析输出即锚清单本体）**

```
knowledgeHierarchy: [
  { bigConcept: 单元/主题级,                 ← 第 1 层：仅作归属分组，【不取为锚】
    coreKnowledge: [                        ← 第 2 层：锚清单本体，【每条 = 一个锚】
      { name, level, specificConcepts[], suggestedQuestionTypes[] } ] } ]
```

- 取锚 = `flattenAnchorTree` 直接读第 2 层，**零解释余量**

- 第 3 层 `specificConcepts` = 最小单位层

**1.2 粒度判据（写死在结构定义内，全学科统一）**

- 第 2 层条目 = **可独立成题 / 可独立教学组织的考点**（锚的定义）

- **最小单位强制下沉第 3 层**：单个字、单个词条、单个符号、单个数值、术语碎片

- 反例自检：第 2 层出现"人/口/手"式单字名 → 违规，须下沉

- 学科分支只决定"提取哪些要点形态"，**不改层角色、不改粒度判据**；英语既有"词条 = specificConcept"提升为**全学科通用判据**

- 判据用**语义判据 + 反例**，**不写数字区间**（防诱导删减）

**1.3 入库校验（用户强调）**

- 重分析结果的**解析入库须按锚树契约校验**；结构不符 → **不落库**（重试/报错），确保"存储即锚清单"

- 校验**只判结构、不改内容**（防"削足适履"删已提取内容）

**1.4 迁移（B2'）**

- 用**现有逐章"分析提取"入口**重新分析全部已分析章节（**不新建批量入口**）

- 验收：**锚粒度诊断**（每章锚数 / 短锚占比(名长≤3字) / specificConcepts 条数分布 / 绑定状态分布），覆盖全部已分析章节

- 将来标准若再变，再考虑 B1'（标准段哈希机制）；**本次不建机制**

**1.5 边界与防呆**

- **不影响"分析什么"，只影响"放到哪一层"**：学科提取规则原样保留；被下沉的条目照样被提取，信息量不减

- **双向盯防**（三指标一起看，单看锚数会被"凑层"骗过）：过细（锚爆炸、调用爆炸）／过粗（锚太少、漏考点）

**1.6 锚点清单的呈现（因材料来源变更而新增）**

- 锚点清单**按章分组**（锚数据自带 `chapterTitle`），**章序与原文一致**

- 呈现形态：`【章名】考点A、考点B、…`

- **对应关系取"章级"**：多条锚共用一个章标题是正常形态；锚只需知道"属于哪一章"

### 2. 材料来源（A15 · ✅ 已定，取代原 A2/A3 的 browse 方案）

**2.1 结论**

- **取消 browse 机制，整体移除**。理由：browse 原为解决"原文注入太长"而设计；压缩方案已解决注入问题，保留无收益（非最优）

- **材料 = 程序直接读取"勾选章节的完整原文"**（按章顺序），不再做"锚→绑定片段"取料

**2.2 由链路变更产生的连锁调整**

- 工具轮 / 上下文累积 → **消失**（无 browse 轮，单次请求）

- A3（程序注入 vs 模型自取）→ **整条消失**（材料由程序读取，不存在"模型自取"）

- A2 的"强制 browse 力度" → **失去意义**；契约只剩 **引用约束 + 覆盖要求**

- 上下文窗口压力 → 输入侧不再紧张（V4 窗口 1M，且材料经压缩）

- `copyGuard` 比对语料 → 由"锚绑定片段"改为**勾选章节原文**（语料更全，检出更强）

- 锚→片段绑定（`coverageAnchor`）→ 退化为**仅用于缺料诊断**，不再是取料依据

- A10（绑定片段去重）→ **不再是问题**（读整章原文本就不重复）

- "未浏览章确认"（`browseAutoFill`）→ 随 browse 移除而**失去意义**，一并移除（避免双重机制打架）

**2.3 引用约束（保留，不可砍）**

- `mode === 'full'`（知识型）→ **可引用/归纳原文**

- 其余（命题型）→ **参考-only**（素材仅供理解、题干与情境自拟）

- 防搬抄守门 `copyGuard` 对非 full 模式保持开启

**2.4 明确不做的事**

- **不做逐锚"是否被压掉"的反查**（用户判断：没有支点、不精准、无意义）

- **不把锚点掺进压缩输入**（见 3.3 防假压缩）

**2.5 材料来源对象（A16 · ✅ 已定 2026-09-11 用户定「甲方案」）**

> 🔴 记录说明：本条为讨论中已确认、但**此前漏记入本定稿**的决定（实施自检时发现）；现补记为准。

- **主路径**：材料来源对象 = **勾选的目录直接对应的真原文**（程序直读整章，按章序）

- **未分析 / 仅目录章（降级目录模式）**：**锚点 = 目录**——章名与子标题作为该章锚点进入【锚点清单】（按章分组），**不再从覆盖范围消失**（替代随 browse 一并移除的【覆盖范围·目录】声明）

- 未分析章**不再**因缺少锚树而被【锚点清单】漏掉；子标题取目录树（深度 ≤3），子标题缺失时以章名为该章唯一锚点

**2.6 未分析章节的原文（A17 · ✅ 已定 2026-09-11）**

- **"有原文但未分析"的章：真原文照压**——该章真原文随卡携带并参与【压缩原文】，**不得丢弃**（旧实现只保留目录文本、真原文仅用于打日志）

- 纯目录章（确无原文）无原文可压，材料即目录文本；生成仍按目录 + 课标推断命题（既有语义不变）

- 与 §2.5 合起来即：**降级只降"锚点粒度"，不降"材料完整度"**——原文该读的照读、该压的照压

### 3. 原文压缩（A4 · ✅ 已定）

**3.1 三段工作流**

```
③-a Map     分批压缩原文（批预算自适应；按章/节自然边界切分）
③-b Reduce  归并成一份连贯、有界、保真的压缩原文（按原顺序拼接；超窗则递归折叠）
④  Stuff    一次成文
```

**3.2 压缩语义（关键，与旧研读本质不同）**

- **压缩对象 = 全部教材原文**（保真压缩：保留原文自身的内容、顺序与结构）

- **不是**按覆盖点写"理解 + 引用"的笔记（旧研读），**不引入"批/覆盖点"第二套组织**

**3.3 防"假原文压缩"（硬约束）**

- 压缩的**输入必须是纯教材原文**

- **锚点不得混入压缩文本、更不得被当作素材改写**——否则产出的是"锚点清单的复述"（假压缩）且与清单重复

- **锚点只在"清单"里出现一次**

**3.4 压缩程度与保真**

- **大范围可显著压缩**，压缩比不设固定值、自适应

- **底线 = 锚点与压缩文本能"对应到"**（章级对应即可）

- 压缩须**保留原文结构与关键事实**（不得删栏目、不得改写事实）

- **压缩比按契约模式分流**：`mode === 'full'`（知识型，含**默写**/知识梳理/复习）须**保留原文表述与原句**（默写答案即原文原句）；命题型（practice/special/reading/exam）**可大压缩**

**3.5 分批与拼接**

- Map 分批按\*\*章/节（自然边界）\*\*切分

- Reduce 按**原顺序拼接**（不产生新的组织，拼接处无缝）

**3.6 分节标题的定义与边界（用户提问澄清）**

- 分节标题 = **原文自身的结构标题**（章标题 / 原文自带的小标题），属**原文维度**

- 锚点清单 = **考点维度**；二者性质不同，**保留原标题 ≠ 引入锚点**

- **边界：只保留原文已有的标题，绝不新造**；若原文无标题，压缩文本保持连续（不虚构标题），抗遗忘改靠"保留原文段落顺序与首句"

**3.7 材料分档：不硬性压缩（A4-10 · ✅ 已定 2026-09-11）**

> 用户提问："单目录的样本够权威吗？能全局采纳吗？如果不能，可否不硬性压缩呢？按情况灵活处理呢？"

- **背景（原实现的缺陷）**：此前材料非空即压缩（`if (rawSections.length)`），哪怕只有一章 5872 字（≈4500 token，1M 窗口完全吃得下）——**白花一次（可能多轮）压缩调用 + 白担一次保真损失 + 多一段等待**，而收益极低（这点输入既不挤占输出，省下的输入费还抵不上压缩本身的调用）。

- **规则（分档）**：**原文 token ≤ 阈值 → 直放原文**（保真最高、省一次调用）；**超过阈值才走 Map→Reduce 压缩**（此时压缩才真正有价值：省每轮重发的输入费 + 抗"中段遗忘"）。

- **阈值 = `min(上下文窗 × 3%, 单次输出帽 × 25%)`**——两处都是推导量，非拍死常量；窗/帽未知时按"需要压缩"保守处理（保持既有行为）。

- 日志明确区分两条路（`材料=整章原文直放` / `材料=整章原文压缩`），实测一眼可见。

- 与 §3.2 的关系：§3.2 的"压缩对象 = 全部教材原文、保真压缩"**是大材料路径的语义**，并未被推翻；本条只是补上"小材料不值得压"的分档前提。

### 4. 写作期（✅ 已定）

**4.1 输入三件与顺序（固定）**

```
锚点清单（开头） → 压缩原文（中段） → 委托书（末尾）
```

- 依据 LLM **首尾强、中段弱**：委托书（最高优先级指令）末尾锚定；锚点清单置开头（让模型"带清单读素材"，利于锚点↔素材对应）；压缩原文（素材，非指令）置中段

- **抗中段遗忘**：压缩文本按原文结构分节（见 3.6）

- **可选极短指针（非重复）**：委托书内加一句"覆盖范围以开头锚点清单为准、素材以中段压缩原文为准"——仅作指针，**不复述清单内容**

**4.2 输出组织基准（承接 A12 结论）**

- 提示词明确：**输出组织一律以委托书【教辅结构】的栏目序列为准**

- 理由：点名清单仍是"覆盖点"组织，与栏目结构是两套组织；必须明确以栏目为准，防 A12 机制 B 残留

**4.3 一次成文**

- 一次请求、单次输出全文（"一气呵成"）；**不做分段组装**

- 截断续写链保留（既有机制）：截断时续写补齐，输出仍连续

**4.4 交付前核对**

- 🔴 **栏目级完整性核对 → 取消（2026-09-11 用户定）**：**做的意义不大**——**栏目结构是"大类"，每个大类下面才是大题、小题**；把"大类栏目名集合"与正文标题集合比对，既漏不掉真正会丢的层（大题/小题），也检不出价值，反易误报（模型可合并/改写栏目名，且蓝图只给框架、内容与题组交模型）。**不实施**。

- **题号连续性核对**（既有机制，已实现）——**这才是真正兜住"断题/漏题"的那道闸门**：正文内 + 出口 + 定稿后共 3 处 `detectBodyNumberingGap`

**4.5 跨点连贯（A5 · ✅ 已定：不新增机制）**

- **不新增"骨架先行"**：写作已是单次成文，不存在逐批拼接；"全局骨架"本就存在 = 委托书里的【教辅结构】栏目序列

- 保障 = 4.2（输出组织以栏目为准）+ 4.4（栏目级核对）

- 章节/题号/难度梯度等全局属性由【教辅结构】承载，**不另设机制**

### 5. 两次生成 / 一次生成（既有机制，沿用）

- 按资料类型决定：`auto` → 纯题型走 **split（两次生成：正文一次 + 答案页一次）**；知识型走 **once（一次生成）**

- 本次方案**不改**这一步的形态；答案页与正文各自调用

**5.1 答案页输入前缀（A6 · ✅ 已定）**

```
压缩原文（仅 mode === 'full'） → 正文全文 → 委托书
```

**不带锚点清单**（2026-09-11 用户采纳建议）。理由：

- **写作期**的锚点清单决定"写什么范围"，有价值；**答案页**的答案范围**由正文实际题目决定**，锚点清单几乎无用

- 锚点清单会引入"第二套组织"——模型可能按考点而非按正文题目组织答案，导致答案与题目错位（A12 机制 B 的形态）

- "答案不缺漏"由"**逐题对齐正文**"天然保证（正文有多少题就答多少题）

**顺序依据**（同写作期：首尾强、中段弱；指令末尾；操作对象紧邻指令）：

- 前：压缩原文（仅 `full`）——参考素材（先素材、后题目的自然阅读顺序）

- 中后：**正文全文**——**操作对象**，紧邻委托书，生成时正对着题目

- 末尾：**委托书**——最高优先级指令（答案规范），recency 最强

**其余规则**：

- **必需项 = 正文全文 + 委托书**（既有约束：答案页只对正文中的练习/自测作答、严禁复述正文梳理）

- **压缩原文仅** **`mode === 'full'`** **带上**（答案常需原文精确表述，如默写/原句）；命题型（practice/exam/special/reading）**不带**，题目自带情境与素材，且避免"照搬原文作答"

- **答案组织以正文题目为唯一基准**

- 可行性：正文全文体量 ≈ 一次成文的输出，1M 窗口下无压力

### 6. 参数自适应（A14 · ✅ 已定）

**6.1 原则（用户定调：参数类都自适应，不硬编码）**

- 建**引擎能力表**（provider/model → 上下文窗、最大输出）；所有预算由"能力表 + 实际输入量"推导，不散落常量

- **输出护栏自适应（✅ 已实施 2026-09-11）**：生效帽 = `min(引擎物理上限, 偏好层成本闸门)`；
  **单次帽 / 预期额度 / 硬顶 / 续写轮次全部推导**（`src/utils/outputQuota.js`）——
  单次帽 = `min(引擎帽, 类型槽帽, 需求×缓冲)`；预期额度 = 单次帽 ×(1+所需轮次)；
  **硬顶 = 预期额度 + 1 轮**；轮次由硬顶推导（**不再是写死的 `MAX_CONT=6`**）；
  **每轮续写帽随"已产出"递减**（旧实现每轮都给满 → 总输出无上界，那才是总成本失控的真正来源）。

- **两层额度 · 停止条件（2026-09-11 用户定"先保完整、再防失控"）**：**预期额度只报警、不停止**
  （超支在生成报告里可见："已超预期额度 X%，为保证完整继续补齐"）；**唯一叫停线是硬顶**。
  停止条件只有三个：① 写完（不再截断）② 续写无效（重复/过短）③ 触硬顶。真写不完仍判失败重来，
  不交半成品（保持"残次品不放行"）。

- **唯一可调量 = 成本闸门**：`generationSettings.outputCeilingTokens`，**2026-09-11 用户裁定默认 192K**
  （64K → 128K → 192K：整本书按单章实测密度推算约 12 万 token 输出，128K 仍在边界上；而
  `max_tokens` 只是"允许量"不是"目标量"——模型写完即停、篇幅纪律已注入全部输出路径，**给宽不花钱**）。
  它**不是**散落在链上的固定常量，而是偏好层的一个可调值；链上已无 `MAIN_TOKEN_CEIL` 之类的硬编码。
  ⚠️ 思考模式已关闭（用户实测口径），故"推理与正文共享 max_tokens 导致正文被挤"这条截断成因不存在。

- **批预算**：按阅读质量自适应（不被窗口逼小），**不按学段/学科各配一套数字**

- **批数 = 材料量 / 批预算**，天然适配学段/学科差异；批数多时用**并发**压缩总耗时

- **学科×学段材料量诊断**（并入 A1 诊断），验证参数是否合理

**6.2 引擎窗口事实（2026-09-11 联网核实）**

- `deepseek-flash`（= V4.1-Flash）/ `deepseek-v4-pro`：**上下文 1M tokens、最大输出 384K tokens**

- 应用侧现行护栏为 64K（`resolveEngineOutputLimit`），低于模型上限 → 按 6.1 改为自适应

- 纠偏：在 1M 窗口下**整册不撞窗**，"整册必须分片"的旧结论作废；瓶颈转移到**输出侧与长输出完整性**

**6.3 与设置页系数设置的关系**

三层分工：

- **偏好层**：设置页 `budgetByType` 的 `tier`(economy/balanced/full)、`custom`(手填)、`cap` → 决定"想要多少"（coef × 勾选原文量）

- **校准层**：实测采样 `getCalibratedCoef` → 修正"贴合度"

- **物理层**：引擎能力表（新增）→ 决定"最多能给多少"

**规则**：`最终帽 = min(偏好层帽, 物理层帽)`——用户设置**突破不了物理上限**；物理上限**也不覆盖用户的保守设置**（取更严者，互补而非累赘）。

优先级：

- **1 级** **`custom`（手填）**：校准**不能**覆盖（这是显式的覆盖意图）

- **2 级** **`tier`（三档）**：校准**可以**覆盖（档位是"一次性定好的基线"，校准负责修正到实测贴合度）

- **3 级** **`cap`**：不能突破（硬顶）

**默认数值的分工（2026-09-11 用户定调）**

- **出厂默认数值由实施方（AI）充分调研后确定**——目标"数值合理够用，用户基本不会动它"

- 待调研项：各资料类型 `coef` / `cap`、压缩批预算、压缩比（按 `mode` 分流）、输出预留（上下文窗 − 输入预算）等

- 依据：`budgetCalibration` 现有口径 + 实测采样 + 引擎能力表

- **其余可调项照用户偏好设置**：`tier` 三档可选、`custom` 手填优先、`cap` 可改

**配套（数值可见）**：设置页每个槽显示**三值**——`基准值 → 校准值 → 生效值` + 校准样本数 + "恢复基准"按钮；校准自动生效但**不静默**。

1. **每条决议必须写成可验收断言**（"实施后应能观测到 X"），不得只写方向性描述。

### 5.2 实施对账规程（专防"缺胳膊少腿"）

4. **提交信息必须引用断言编号**（如 `A4-3/A4-5`）。
5. **提交后回填台账**：状态 + 证据 + 提交号；**无证据的断言保持"待实施"**。
