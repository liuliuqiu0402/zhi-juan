## 2. 关键机制现状核对结论

- 工具循环浏览（browse_textbook）**已存在**且为真函数调用（tools + tool_choice=auto + 轮循环 + 漏章确认 + 收敛判定），非"附件直灌"——此前判断需修正：复位不是"从零建工具循环"，而是"把 browse 从超预算兜底改为常态研读通道 + 返回物治理（练习段过滤/锚级粒度/随返引用约束）"。
- 直灌路径（小范围 ≤ 素材预算）：素材仍以 materialBlock 单次随委托给——即本课若 ≤6000 会直灌；本课 7027>6000 走了 browse 但仍照搬（返回物含练习原文+章级整批）。
- 预算体系已含：动态帽、once 两段合计兜底、触顶升级、1.25 安全缓冲、引擎上限护栏、截断续写链——"宁多勿截、绝不停静默截断"的骨架已具备，复位补研读成本模型即可。
- 覆盖重试（缺漏必覆盖）、缺料上抛、差异化复生成均与准绳"程序只报不改、回流模型重做"同向。

## 3. 与准绳的差异清单（复位改动点）

- G1 研读轮不存在：需新建（批粒度/批摘要校验/研读总账/状态机"研读中→可委托"）。
- G2 委托书位置与纯度：instruction 在 browse 首条与 materialBlock 同批给；且 instruction 内程序性知识段待核（rc/vp/渲染示例）——复位=委托书纯净（程序性知识移出委托正文）、时序后移（研读完成后追加）。
- G3 browse 返回物：需加练习段过滤、锚级/示范优先、随返引用约束（"可简短引用，不得成段照搬"）、白名单仅覆盖范围内。
- G4 生成方式：**D1 定版（2026-09-07）**：split（正文+答案页独立调用，温度分层）/once/auto 全部维持不变；"一次成稿、不分段不拼接"的含义 = 禁止"逐题/逐块多次生成后程序拼接"（现状无此路径，复位亦不引入），非禁止正文/答案页的结构性两次调用。阶段 3 按此执行。
- G5 素材库前置：Step1 段类型枚举补"拓展/文化"、锚范围性质判定（拓展锚不进必覆盖）——`contentCards` 段类型字段与 Step1 分析 prompt 待核（见 O1）。
- G6 一次成稿后的出稿校验路径沿用现有 examValidator/contentSanity（只报不改）与质检面板。
- G7 **废除直灌路径**（2026-09-07 用户拍板）：materialBlock 随委托拼接不再存在；素材唯一途径 = 研读轮分批 + 写作期 browse + 研读总账；大/小范围判定与"超预算回退单次注入"一并删除。

## 4. 待核项结论（2026-09-07 已核）

- R1 委托书拼装来源：`GenerateModule.vue`（`loadInstructionFromLibrary` 按三维度匹配自动组装 → `instructionDraft` 可见可编辑 → 生成时作 promptBase）；区块级来源标注由 `utils/instructionBlocks.js`（annotateInstructionBlocks 旁路）提供；rc/vp 等程序性知识段以"指令库条目"身份被拼入委托正文——复位（G2）的移出点 = 指令库条目构成（实现阶段列逐条目清单）。
- R2 素材构建：`buildMaterialBlock` 定义于 `useAiGenerator.js:4315`（按知识点检索+分级限量）；`MATERIAL_CHARS`（generationConstants:37-40）：exam 10000 / practice 6000 / special 5000 / reading 6000 / summary 8000 / review 8000 / preview 3000 / dictation 3000 / errorbook 2000——本课 7027>6000 触发 browse（已核）；perBrowseCap = budget/6 clamp [800,1800]（useAiGenerator:3995）。G7 废除后 MATERIAL_CHARS/大小范围判定/回退逻辑一并清理。
- R3 语英 Step1 字段：锚树来自 `chapter.knowledgeHierarchy` 归一树（useAiGenerator:798 组装 anchorTree）；语英 content 型卡形态（O1）需在实现阶段读取语英章节的 knowledgeHierarchy/段字段样例定"语料卡"形态（保留为 O1 实施项，不空中设计）。
- R4 截断续写：`detectTruncation`（finish=length/reasoning_capped 且 >200 字，useAiGenerator:923-926）+ `allowContinuation` 自动续写（1373-1377+，正文/答案独立续写计数与去重兜底）——续写=模型在同一输出流上继续产出（非程序拼接），与准绳一致；"逐题/逐块生成拼接"无此路径（D1 已证）。
- R5 预算校准系数：`utils/budgetCalibration.js` 分桶主键=类型×学科×五档学段（与三维度注入同构）；产出率校准（字符产出/勾选原文字），优先级 用户 custom > 校准覆盖 > 播种默认；档间比例 精简:均衡:充分 ≈ 0.72:1:1.25；校准仅作用于 body/once 槽。复位新增研读成本模型时复用其"读校准/写校准"接口。

## 5. 前提状态

- P1 引擎（2026-09-07 更正）：复用**应用设置中用户填写的引擎配置**（长上下文多轮+工具调用+长输出能力由该引擎承担）；端到端验证采用**应用内实操导出模式**（用户在应用内按复位流程生成，导出产物+生成日志供审计），无需把 API Key 移交外部环境。

- P3 基线：全量测试与构建待复位实施前跑一次确认（当前预期 78 文件 1378+ 用例绿）。

## 6. 结论

复位工程的大部分"从零建设"假设不成立——工具循环、预算护栏、缺料上抛、覆盖重试均已存在且方向与准绳大体同向；真正的结构性缺口集中在：**研读轮不存在、委托书纯度与位置（G2）、browse 返回物治理（G3）、生成方式定论（D1）、素材前置（G5）**。实施应以"改造既有机制"为主，避免推翻重写。
