## 二、习题类大题标题方案（D4，待确认形态）

现状：practice 栏目 h2 = 蓝本固定栏目名（基础建构任务/探究进阶任务/迁移创新任务），模型在 h2 下直接排题。
问题：栏目名是"任务形态"（建构/进阶/迁移），不是"内容线索"（练哪些知识点）——学生/教师无法从大题标题预知本栏内容。
方案（择一）：
- 方案甲（推荐，低破坏）：h2 保留栏目名，栏目名后追加内容副题冒号短语：`<h2>一、基础建构任务：小数乘法的意义与算理</h2>`，副题由模型按本栏实际覆盖的核心知识概括（≤18 字）；不改渲染契约与答案区结构。
- 方案乙（结构增强）：栏目名上方（h1 之下）输出本卷"内容导览"段落——与"声明≠覆盖"条款冲突（用户已否过覆盖声明形态），不推荐。
- 方案丙：不动标题，仅优化栏目 note 注入——不解决用户指出的问题。

## 三、情境设置评估（现状与建议）

现状（设置面）：命题风格单选——统一情境类（unified_context/unit_context/context_chain）与情境融合（scenario_each，默认 practice 等）；融合时"恰好 3 个情境"AI 自定。
结论：够用性不足，三个缺口：① 情境数固定 3 与栏目/题量脱钩（D3）；② 无主题互斥与承载上限（雷同源）；③ 无学科情境词库/覆盖锚引导（情境与考点的贴合靠 AI 自觉）。
建议与 D3 合并实施；情境承载上限落实为生成期约束（每情境最多 N 题）+"情境主题词频守门"（已实现）双保险。

## 四、治理原则（防再犯）
新规则/既有规则修改须声明三维度切片并写入本表；全学科 QUALITY_BASE 只放学科中立条款；理科算术、语文语料、低段配图等学科/学段语义一律下沉到对应纪律/蓝本/守门分片。
