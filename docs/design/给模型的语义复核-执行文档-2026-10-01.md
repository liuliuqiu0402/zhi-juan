# 给模型的语义复核 · 执行文档

> 2026-10-01 · **执行与验收同一份**。尺度：**一句话能解决的，绝不用两句。**
> 本文件只定三件事：**任务 / 范围 / 执行标准**。附条与纪律细目见 `docs/design/指令改动标准-可机检清单.md` §六，**不重抄**。
> 🔴 **§4 是核心**：每次改动照它按序做，一步不跳——这是防"丢三落四"的唯一办法。

## 0 改之前必须知道：实发长什么样

- **一次生成 ＝ 多次独立调用，每次调用 ＝ 一份"实发"**（实发是**复数**）：
  正文请求 / 答案页 / 听力抽取 / 听力翻译 / 压缩 map / 压缩 fold / 教材分析提取
  / **知识图谱构建** / **教材页知识点提取（多模态）** / **统一情境生成** / **变题生成（编辑器）**。
  （**"层级·卷别提示"不是独立调用**——它的产物 `levelBlock` 由 `buildInjectionInstruction` 拼进**正文请求**里，2026-10-02 改准；`buildPaperKindHint` 为界面提示、不进模型。）
  🔴 **2026-10-02（④精准·范围补齐）**：后 4 类此前**从未登记**（原口径只数了 7 类）——登记的权威名单见
  `caliberRegistry.PROMPT_CALL_SOURCES`（现 **10 类**）；另有一处**通道文本**（「目录模式卡」在锚点清单/素材通道里夹带指令）
  同批补登记进 `PROMPT_INLINE_SOURCES`。
- **正文请求的组成与顺序**（唯一事实源 ＝ `injectionManifest.BLOCK_DEFS`）：

| 角色 | 顺序 |
|---|---|
| system | 渲染契约 → 质检提示 → 底线兜底 |
| user | 锚点清单 → 压缩原文 → 素材使用约定 → 组织方式 → **委托正文**（生成期末尾追加【组织风格】/第二类型起的【差异化要求】）→ 模板对标 → 情境框架 → 差异化 → 输出约定 → 尾约束·全文自洽 → 尾约束·资料内多样 |

- **每块自带 `lib`**（＝点击跳到哪个库）：`instruction`→指令库；`render-contract`→渲染契约库；`rules`→规则库；`builtin`→程序内置·无库可编辑。
- **"程序附加段"是通道名、不是来源名**——判来源一律看 `(lib, key)`。

## 1 任务

把所有**会发给模型的语义**逐条逐句过一遍，做到：

1. **语义精准**——判据词／阈值／限定词／指向对象一字不失；判据须**可自判**（带对象／阈值／清单／算式），不得只有形容词。
2. **表述简短**——能一句的只写一句。
3. **以结果反推**——先想清"这份资料最终要长成什么样"，再倒推"该写哪条判据"。
4. **结构清晰**——段界分明、一条一义、关键判据放首尾。
5. **同一份实发内不多块同义**——同一件事只留一处正句，其余做**真引用**。
6. **合规**——遵守经检验仍成立的既定规则；不盲从、不照抄。

### 2.3 用户四问（逐条必须答）

| # | 问 | 落点 |
|---|---|---|
| ① | **对账**（正反交叉） | 正向 源→实发（防漏采集）／反向 实发→源（防漏登记）／注入点反查（元校验）；**实发每一句必须有主**；先归零→再按份改→滚动对账；**禁止靠扩容源定义凑数** |
| ② | **给模型 vs 给程序** | 库内 669／47；**读懂内容才能定的事归模型**（答案是否满足题干、材料是否被完整使用、是否超学段、覆盖面）；**不需要理解语义、能确定性算/查的归程序**（分值账目、题号层级、页码分页、字符归一、占位替换） |
| ③ | **跳转不破坏** | 改动后实发每段仍能映射到 `(lib, key)`；无法映射者显式标"程序内置·无库可编辑" |

| 类 | 通道 | 内容与来源 | 可跳转 |
|---|---|---|---|

| 3 | **用户消息侧其余块** | 锚点清单／压缩原文／素材使用约定／组织方式／模板对标／情境框架／差异化／输出约定／尾约束×2（多为库外 `builtin`；**输出约定转引库内 `PAPER_OUTPUT_CONVENTIONS`**） | ⚠️ 多数无库可编辑 |
| 4 | **程序附加段（system）3 段** | **全部来自库内**：渲染契约库／规则库／指令库兜底 | ✅ 三个库 |
| 5 | **独立调用** | 答案页／听力抽取·翻译／压缩 map·fold／教材分析提取／**知识图谱构建／教材页知识点提取／统一情境生成／变题生成**（**"层级·卷别提示"不在此列**——它拼在正文请求里，2026-10-02 改准） | 已登记（`PROMPT_CALL_SOURCES` 10 类，2026-10-02 补齐后 4 类） |

### 2.4 生成配置项：进模型者要过，执行侧参数不过

进模型（10 项）：生成方式（split／once／auto）／素材通道（auto／full／anchor）／第 3 层概念注入／组织风格／模板对标／情境框架／差异化要求／**卷别·层级**／**工具库条目启停**／**三维度选择本身**。
不进（执行侧参数）：温度／思考预算倍数／单次输出闸门／每类型动态预算／系数下限——**不进语义判定**，但列为"重复成因"的怀疑对象。

### 2.5 排除项

- **不存在的三维度组合（笛卡尔积 675 − 真实 486 ＝ 189）**：**不真实，不得混入**——一律按 ① **门控封杀**，不进覆盖口径、不单列登记。
- 注释、UI 文案、日志、存储键、纯数值参数。
- 素材（锚点清单／压缩原文／上次正文）＝**输入**，不是指令源。

### 2.6 份数
三维度组合 × 调用类型，再按改变实发的分支展开。进度按**份 × 句**记——**未登记＝未过**。

## 3 执行标准：八步（**按序执行，不得颠倒、不得跳步**）

**顺序递进**：前一步不过 → 先处置、再从断点续判，不得越过没过的那一步。
**留痕完整**：该条最终 **8 项全落点**，逐项写"过 / 不过（已处置）/ 不适用"。

| 步 | 判什么 | 怎么处置 |
|---|---|---|
| ① **三维度** | 这条该不该出现在"这个学段×学科×资料类型"里？组合须**真实存在** | 越界 → **优先门控**（只在该组合不注入），其次才删；**不存在的组合封杀** |
| ② **课标** | 按课标处——**原文还是原义**？限定词有无被偷换？有无编造？出处受控吗？ | 偷换＝改回；编造＝删或改中性；课标没写的不加 |
| ③ **啰嗦** | 同一意思能否更短？ | 能一句只写一句；两处同义合并；**删前先过 §4.1 三句问** |
| ④ **精准** | 换短后判据词／阈值／限定词／指向对象有无丢或变？是否真指向要产出的结果形态？ | 判据一词不失；丢了即回补——**精简是改写，不是删判据** |
| ⑤ **诱导** | 题型名暗示？指向性诱导（设问/作答路径、自造举例、否定式植入）？ | 一律清；举例改占位或删 |
| ⑥ **拼接** | 与**同一份实发**其他块拼起来，有无重复／啰嗦／打架？段界与段内结构是否清晰？ | 判重＝**作用结果相同即重复**；一处正句＋其余引用；口径＝**同一份实发内**，禁跨份累计 |
| ⑦ **排序** | **位置与先后**是否符合模型遵守习惯？（块内：一段一主题、同主题相邻；整份：关键判据放首尾、长素材不与判据混排） | 不合则重排，**不靠加字** |
| ⑧ **质量** | 照这条发出去，产出的资料**能不能到高质量**？ | 无真机通道须**标注判定层级**（纸面推演／程序校验／真机实测），**禁止无依据断言** |

## 4 每次改动的固定动作（**坚决按序执行，一步不跳**）

> 这是本文件的核心。照做就不会丢三落四；跳过任何一步都会出事。

1. **定位**：这句属于哪个源（库内／库外哪张表）、哪个通道（类 1–5）、哪个 `(lib, key)`。
2. **读懂它**：先搞清"当初为什么加这句、防的是什么事故"——**先读懂，不盲删**（跳出现有内容的影响 ≠ 无视它）。
3. **八步判定**：①→⑧ 按序走，逐项落痕（过／不过（已处置）／不适用）。
4. **分层定处置**：契约（协议/固定件，删了崩预览导出）→ 不动；判据（须可自判）→ 改准、写更短；取向 → 压成一句或删。
5. **动手改**：删／并／引用化／门控／重排。**一处正句，其余引用**；引用须指向**真实会被注入**的段。
6. 🔴 **同步所有引用方（本节最容易丢的一步，本轮就漏了 2 处）**——改完文本，**逐个检查并同步**：
   - 同义计数登记：`src/config/caliberRegistry.js`(CALIBERS)／`tests/config/intraRequestDuplicate.test.js`(allow)；
   - 复核动作登记：`tests/config/reviewActionGuard.test.js`(条目数与 anchor)；
   - 源登记：`caliberRegistry` 的 E／E2／E3／E4 表（删了源要同步删登记，否则"假登记"即红）；
   - 单源字面：`tests/config/singleSourceGuard.test.js` 保护的字面只能在一处；
   - 逐字断言：把锁死全文的 `toBe`／`toContain(全文)` 按新口径改为**判据级断言**（不再锁每个字）；
   - 面板/消费方：`GenerateModule.vue` 等对已删函数的引用。
7. 🔴 **跑测试**：`npx vitest run tests/config tests/recipe tests/utils`；**红了就地改准**（属"改准"，不再"只准收紧"）。
8. **留痕**：每处改动留"**原句 → 短句**"＋理由。
9. **登记进度**：覆盖台账按"份 × 句"记；**未登记＝未过**。

### 4.1 动之前先过三句问（**是自问，不是禁令**）

| 问 | 答得出时怎么做 |
|---|---|
| 删了会有什么风险？程序接不接得住？ | 答得出"接得住"就删（把校验/兜底落进程序＋测试）；答不出先留 |
| 它是不是某条判据的**唯一正句**？ | 是 → 只能改准或挪位置，不能删；只有复述才可删，且删前确认正句仍在 |
| 它是不是在替另一条前置**兜底**？（自检块／复核块） | 先找它在替哪条前置兜底 → **把前置改准、补全** → 验证足够 → **才删** |

### 4.2 重洗牌心法（用户 2026-10-01 补充 · 最高处置原则）

现有文本里**大量是"多次修复叠加"的产物**（补丁或纯堆积）。处理时：

1. **跳出现有内容的影响**，但不**无视**它；2. **当作从零设计**，按需求把这条重写一遍"精准简短"的指令；3. **以结果倒推**——"要产出这个结果，这条是不是必需？"不必需就删；4. 严守**任务／范围／执行标准**，不越界、不另立。
   **判准不是"它原来在不在"，而是"结果需不需要它在"。**

### 4.3 明令不做

按字数比例砍／"看着像解释"就批量删／为凑短删判据／一次动一整类／无依据地删。**每一处都必须留"原句 → 短句"＋理由。**
