# 导图族 · 图种规格（印刷友好 SVG）

> 适用前提：**学生看的成品资料，要进 PDF/Word，必须印刷友好**。
> PDF 通道（puppeteer）吃内联 SVG（矢量）；Word 通道（docxBuilder）只吃光栅图 → 由调用方光栅化。
> 统一契约、印刷约定、共用工具见 `src/utils/diagrams/shared.js` 头部注释。参考实现：
> `src/utils/diagrams/mindmap.js`（**先读它**，风格/命名/测试口径照抄）。

## 每个图种模块的统一要求

- 文件：`src/utils/diagrams/<type>.js`；**只从 `./shared.js` 取公共能力**，不新增依赖。
- 双导出：
  - `export const layout<Type> = (spec, opts = {}) => ({ nodes, width, height, metrics })`
  - `export const build<Type>Svg = (spec, opts = {}) => ({ svg, width, height, nodes })`
- `nodes` 已平铺，坐标为**最终像素值**（已归一到正数、已含外边距），每个节点至少 `{ id, title, x, y, w, h, lines }`；
  文字行放 `lines`，图形宽度必须由**实测文字宽度**反推（`w = textW + 2*padX`），保证文字不越出图形。
- `width`/`height` 必须为整数，且**所有节点完全落在 `[0,width]×[0,height]` 内**。
- `svg` 不含 `<?xml>`/DOCTYPE，用 `svgHeader()` + `svgPaper()` 起头，白底。
- 印刷约定：无阴影/渐变/外链资源；层级用**线宽+字重+缩进**表达（黑白打印颜色会消失）；字号 ≥ 11px。
- `opts` 通用：`{ fontSize = 13, titleFontSize = 15, maxLabelWidth = 150, palette = DEFAULT_PALETTE, measurer, labelTransform }`。
- 文字一律用 `esc()` 转义后写入。

## 配套单测（每个图种都要有，文件 `tests/utils/diagram<Type>.test.js`）

用 `boxesOverlap` 断言，**不靠肉眼**：
1. 宽高为整数且 > 0；每个节点都在画布内。
2. 节点框**两两不重叠**（`boxesOverlap` 全 false）。
3. 标题文字不丢：`solid(lines.join(''))` 是 `solid(title)` 的前缀（`solid = 去掉所有空白`；
   仅允许末尾 `…` 截断，用 `.replace(/…$/,'')` 后再比）。
4. 出图：`svg` 含 `</svg>`、白底；特殊字符输入（`a<b & "c"`）被转义、文本节点里无裸的 `<`/`>`。
5. 确定性：同输入两次结果一致。
6. 空/单元素输入不崩，尺寸仍为正。

## 1. 括号图 brace.js（整体—部分）

**输入**：`{ title, children: [{ title, children }] }`（一棵树，任意深度）。

**版式（从左到右）**：
- 节点文字框统一风格：`rx=6`、白底、1.3px 边框（颜色同该子树分支色）；文字左对齐。
- 递归：每个节点 n 先算自身文字框；其**子节点整体**排在右侧，子节点之间纵向间距 `gapY = round(fontSize*0.7)`；
  n 的文字框纵向**居中于其子节点跨度**。
- 在 n 与它的子节点之间画一个**简化花括号**（印刷清晰的方括号式）：竖直主笔 `x=braceX` 覆盖子节点跨度，
  上端/下端各一小段横笔（+6px 指向右），中间一段横笔指向 n（-6px）；线宽 1.8px；颜色取 n 的颜色。
  横笔长度 6~8px 固定；`braceX` 距 n 右边界 `gapX/2`，距子节点左边界 `gapX/2`。
- 横向：子节点列起点 = n.x + n.w + gapX；同层节点按"该层最大宽"统一列位（保证同层左边界对齐）。
- 叶子节点无花括号。

**验收**：无重叠；n 与其子节点不同列；父子纵向对齐（n 中心 ≈ 子节点跨度中线，容差 1.5px）。

## 2. 流程图 flow.js（步骤与判定）

**输入**：
```js
{ steps: [ { text, kind?: 'start'|'process'|'decision'|'end',
             branches?: [ { label: '是', steps: [ { text, kind? } ] } ] } ] }
```
`kind` 默认 `'process'`；`branches` 只出现在 `decision` 上，最多 2 个。

**版式（主轴纵向、居中）**：
- 主轴所有框**同宽** = `max(120, 各步骤所需宽度最大值)`，水平居中于主轴中线 `axisX`。
- 形状：`start`/`end` 圆角矩形 `rx=14`；`process` 矩形 `rx=6`；`decision` 六边形
  （`polygon`：左右两端各内收 `notch = min(h/2, 14)`，上下边直，左右成尖）。
- 步骤间纵向间距 `22px`，中间画向下箭头（竖线 + 三角箭头，长 22px，线宽 1.6px）。
- 文字**水平居中**（`text-anchor="middle"`，x = 框中心），纵向整块居中；超宽走 `wrapLabel(maxLabelWidth)`。
- 分支：`decision` 的每个分支排在主轴**右侧**、按顺序自上而下：
  - 从该 decision 的右尖点引一条水平线到分支列，线中点上方放分支标签（小字 11px，白底挡住线）；
  - 分支内步骤纵向堆叠（间距 16px），框宽按自身文字，左边界对齐分支列 `x = branchX`；
  - 分支首框的纵向中心取该 decision 的中心（多分支时以 decision 中心为锚上下排开）。
- 分支内的步骤不再递归分支（v1 上限 1 层）。

**验收**：主轴框之间、主轴与分支列之间**均不重叠**；全部在画布内；箭头/连线不得穿过文字框
（连线只在框间空隙走）。

## 3. 时间轴 timeline.js

**输入**：`{ items: [ { when: '1919年', text: '五四运动', detail?: '可省略' } ] }`（按给定顺序排列，不排序）。

**版式（横向轴）**：
- 主轴水平线 `y = axisY`（画布垂直中线附近），从左到右贯穿；线宽 2px；两端各留 `margin`。
- 每个事件占一个**等宽槽** `slotW = maxItemW + 24`（`maxItemW` = 各事件文字框宽度最大值）；
  事件框在槽内水平居中 → 相邻槽的框天然不重叠。
- 事件**上下交替**：偶数序号在上、奇数在下。上/下事件框距轴 `24px`；
  从轴向事件框引一条竖直**引线**（1.4px），轴上该点画一个 `r=4` 的实心圆点（颜色按序取 `palette`）。
- 事件框内容：第一行 `when`（字重 600、颜色取该事件分支色），随后 `text`、可选 `detail`（`INK`、常规字重）；
  全部走 `wrapLabel(maxLabelWidth)`；框宽 = 最大行宽 + 2*padX。
- 相邻事件在轴上等距，间距 = `slotW`；不同侧的事件框不重叠，同侧事件框相隔 2 槽。

**验收**：所有事件框两两不重叠；全部在画布内；每个事件框与其引线在 x 上对齐（容差 1px）。

## 4. 鱼骨图 fishbone.js（因果）

**输入**：`{ effect: '结果/待分析的问题', categories: [ { name: '人', causes: ['因1','因2'] } ] }`。

**版式**：
- 主脊：水平直线 `y = spineY`，从左侧 `margin` 到右侧；末端画实心三角箭头，箭头右侧放 `effect` 框
  （深底白字 `HEAD_FILL`/`PAPER`，字重 600）。
- 类别**上下交替**沿主脊分布：第 i 个类别在脊上的锚点 `x_i = margin + spineLen * (i + 0.7) / (n + 1)`；
  `i` 为偶数在上、奇在下。
- 每类的**骨**：从锚点 `(x_i, spineY)` 斜向 `+dx, ∓dy`（`dx = 96`、`dy = 62`，即约 33°）画直线（1.6px，类别色）。
- 类别名放在骨末端的小框里（白底、1.3px 边框、字重 600），与骨同向放置（框中心在骨末端再外移 8px）。
- 该类的 `causes` 沿骨**等分内插**：第 j 个因（共 m 个）取骨上 t = (j+1)/(m+1) 处，向该侧**垂直偏移**
  `dy = -14`（框在骨上方，避免压住骨），画一个小框（白底、1px 淡边框、11px 字、`maxLabelWidth=110`），
  并用一条 0.9px 短竖线连回骨上对应点。
- 因的文字框在骨侧排列，必须保证**同一类别的因框之间不重叠**；若某个因框与同类相邻因框（垂直偏移后）重叠，
  改为沿骨方向额外错开 12px 直至不重叠（确定性循环，最多 20 次）。

**验收**：所有框（effect/类别名/因）两两不重叠；全部在画布内；类别锚点 x 严格递增。

## 5. 概念关系图 concept.js（带标注的关系网络）

**输入**：
```js
{ center?: '节点id 或标题', nodes: [ { id?: 'A', text: '概念' } ], links: [ { from: 'A', to: 'B', label?: '属于' } ] }
```
`id` 缺省用 `text`；`from/to` 按 id 匹配，匹配不到则按 `text` 匹配，再匹配不到按索引（`layout` 内做健壮处理，不抛错）。

**版式（环状，不引入力导向）**：
- 中心节点 = `center` 指定者，缺省取**连边最多的节点**（并列取第一个）。
- 其余节点放在**一个圆环**上，按角度均分；排序启发：与中心相连的邻居依次排列，且把与某邻居相连的卫星节点紧挨其后
  （用"邻接分组"做一次线性排列，降低连线交叉）。
- 节点框即文字框（`rx=8`、白底、1.3px 边框、居中文字）。
- 连边：用直线连接两框；端点取**框边界与连线的交点**（不要穿过框内部），线宽 1.4px、`opacity=.8`；
  有 `label` 时在**中点**放小字（11px，`INK`），文字下垫一块白底矩形（`fill=PAPER`）压住连线。
- 半径自适应：从 `r0 = max(150, 环上节点数 * 46)` 起，**迭代增大 r**（每次 ×1.12）直到
  "节点框两两不重叠"成立（最多 24 次；仍不成立则用最后值）。必须保证同一环上相邻节点的框不重叠。

**验收**：所有节点框两两不重叠；全部在画布内；每条 link 都画出了线（线的条数 = 有效 link 数）；
label 文字出现在 SVG 里。

## 统一入口（由主线实现，图种模块不必关心）

`src/utils/diagrams/index.js` 导出：
- `DIAGRAM_TYPES`：`[{ value, label, hint }]`，供 UI 选择。
- `buildDiagramSvg(spec, opts)`：按 `spec.type` 分发；未知类型回落 `mindmap`。
- `diagramToPngDataUrl(svg, { scale })`：浏览器侧把 SVG 光栅化成 PNG dataURL（供 Word 通道）。

> 曾尝试把 `[GRAPH]` 指令块（COORDINATE / SHAPES / BAR·LINE·PIE_CHART）在**本项目内就地渲染**，
> 实现已完成（坐标系 / 几何 / 统计图三组图种 + 表达式求值器 + 适配器 + 分级开关 + 120 条单测），
> 但用户最终裁定**不收回**，相关代码已删除（git 历史可查）。
>
> **不做自动化（用户原话）**："外部出好的图目前只能从 EduRender Studio 导出，复制剪切进来的，
> 不需要做自动插回。"、"我都是导出后再粘图进来的，省去了体积过大的风险。"

**不收回的理由**（当时的实证结论，后续勿重复试错）：

1. **对方更全**：`D:\edurender-studio`（Electron + React，独立项目）覆盖 **65+ 图种、8 个学科**，
   含立体几何、受力、电路、光路、原子与分子结构、实验装置、生物图示等；本项目那 5 类只是残的。
2. **本项目的短板**：`[GRAPH]` 的 SHAPES 契约自带 `XLIM/YLIM/GRID`（坐标轴），**无法表达"几何图形不要数轴"**，
   立体图更无从谈起 —— 硬做必然是"画错比不画更糟"。
3. **体积风险**：粘贴位图约 200KB~1MB/张（base64 再 +33%），本项目 `cloudStorage.ts` 记载过
   "单行 3.4MB → 240s 超时"的事故；矢量 SVG 虽小，但用户既有"导出→粘贴"流程已跑通，无需为省体积引入新链路。

**保留不动的既有能力**（**不要**一并删掉）：

- 生成端照旧输出 `[GRAPH]`/`[IMAGE]`/公式指令（契约见 `src/config/eduRenderContract.js`、`src/utils/directiveBlocks.js`）；
- "复制指令给 EduRender Studio"的出口照旧（本项目出指令 → 对方出图 → 粘贴回排版页）；
- 排版页对已粘贴图片的承载能力照旧（`allowBase64`、Word 导出光栅化链路）。

**本文件描述的导图族（mindmap / brace / flow / timeline / fishbone / concept）与 `[GRAPH]` 无关，继续维护。**

## 修订记录

**2026-09-24 · 印刷可读性告警改为按"缩放比"判定（真实实跑后的误报修正）**

首次真实云端模型实跑（知识总结 + 导图式）结果：模型按约定输出了合法 JSON 的导图块并成功渲染成 SVG，
但告警里出现一条噪音 —— `思维导图 宽 764px，超出 A4 版心，将缩到 0.99 倍（12.9px ≈ 9.7pt 字），印出来可能偏小`。
764px 只超版心（760）4 像素、缩到 0.99 倍、字约 9.7pt，完全能印。根因是判据取错了：
旧判据是"**宽度 > 版心即报**"，而真正伤印刷的是"**缩得太狠**"。

现判据（`src/utils/diagramBlock.js`）：`版心 ÷ 图宽 < PRINT_MIN_SCALE(0.8)` 才告警，等价于 图宽 > 950px；
判定逻辑抽成纯函数 `printReadabilityWarning(width, label)`，边界由单测直接锁（764px 不报、951px 报）。

> 注：这只治了"误报"，"图确实太宽"这件事本身仍未解决 —— 见上方待办的竖版 / 窄版策略。

## 出图边界：结构类图就地渲染，精确图才去 EduRender（2026-09-24 用户定）

> 写下来的目的是**防忘记边界**。一句话：本仓库的导图族一律**就地渲染**，不送 EduRender。

| 图的类别 | 本仓库对应图种 | 谁渲染 | 为什么这么分 |
|---|---|---|---|
| **结构类图** | 思维导图（左右分布 / 向右生长）、括号图、流程图、时间轴、鱼骨图、概念关系图 | **就地渲染**：`src/utils/diagrams/` → SVG（PDF 走矢量；Word 前光栅化） | 结构由我们产出的"节点 + 关系"文本决定，本地渲染即所见即所得；送出去会丢掉矢量与可编辑性、白多一次往返 |
| **精确图** | 函数图像、数轴、几何图形、化学结构式、力/电光示意、统计图、公式 | **EduRender Studio**（出 PNG） | 要按数学定义精确作图（坐标、刻度、比例），本地拼不出来 |
| **配图（写实插图）** | 教材配图、情境图 | **外部 AI 出图**（配图按钮给提示词 → 出图 → 插回） | 本地渲染的观感不如 AI 出图（用户已认定） |

**为什么必须守这条**：EduRender 里"思维导图 / 时间轴 / 流程图 / 体系图"落的是**配图识别器**那条路
（`modules/recognizers/image-recognizer.js`），只会吐一段 `PROMPT:思维导图，中心主题：…` 交给外部
AI 出图，**本地不出图**。把结构类图送过去，拿到的不是"可编辑导图"，而是一张位图加一次往返。

**本仓库两条通道的口径不变**（不因边界划分而变）：PDF 走 puppeteer，吃内联矢量 SVG；
Word 走 `utils/docxBuilder` 的 ImageRun，只吃光栅图，故 Word 前由 `diagramToPngDataUrl` 光栅化。
对侧说明与出图目录见 `D:\edurender-studio\docs\协同边界.md`。
