## 六、逐条逐字复核的"八问固定顺序"（2026-10-01 用户裁定 · 标准）

> 用户原话（2026-10-01）："逐条逐字……每一条都要有如下自问：①首先是三维度……②其次是否符合课标原文/原义……③语义是否啰嗦？④意思是否精准表达了？⑤是否有题型诱导、指向性诱导等？⑥最后按这个三维度实发的时候，与其他的拼在一起后，整体看是否有重复语义、啰嗦语义、语义不一致的地方？"
> 用户追加（同日）："**⑦指令排序，要符合模型遵守的习惯。⑧实发的语义指令，生成的资料内容是否能够达到高质量水准？**"
> 并裁定："**这八问必须按顺序，不能颠倒、不能漏**"；"工具库内、工具库外的所有实发给模型的都这样处理，不能漏，不能偷懒"。
> 🔴 **定序（用户 2026-10-01 · ⑦⑧对调）**：**⑦＝排序（位置与结构）／⑧＝质量**；排序**不只在整份实发要符合，在每一块／每一库内部也要先符合**。

**适用范围（不漏的边界）**：凡**真正进模型请求**的文本一律纳入——工具库（指令库/蓝图库/规则库/渲染契约库/排版规格库/风格库）＋ 库外编码（injectionManifest / programAttach / anchorTreeContract / promptOversize / textbookCompression / themeConfig / useAiGenerator / analysisPrompts / specialDomains / listeningExtractPrompt / listeningTranslatePrompt / levelMapping / coverageContract 等）。**排除**：注释、UI 文案、console 日志、存储键、纯数值参数表。

**判定顺序（不得颠倒、不得跳问；每条都要留下 ①–⑧ 的判定）**

| 序 | 自问 | 判定与动作 |
|---|---|---|
| ① | **三维度**：这条内容符合"这个学段 × 这个学科 × 这个资料类型"吗？**且该组合须真实存在**（用户 2026-10-01：小学无物理、物理自初中起；不存在的组合不得出入口、不得注入、不得借用他学段骨架冒充） | 不符合 ＝ **越界** → **优先"门控"（cell 级，只在该组合不注入）**，其次才删（共享常量被少数越界 cell 复用时**不得全库删**）；越界条款不因"写得好"而保留 |
| ② | **课标**：凡须依课标处（学段目标 / 学业质量 / 内容领域 / 素养名 / 情境要求 / 活动类型）——取的是**原文**还是**原义**？限定词（了解·理解·掌握·运用 / 会·能）有无被偷换？无出处的表述是否属**编造**？ | 偷换限定词＝改回；无出处虚构＝删或改为不点名的中性表述；课标没写的不加 |
| ③ | **啰嗦**：同一意思**有没有更短的写法**？ | 只找重复不算精简；每条都要回答"能不能更短" |
| ④ | **精准**：换短之后，判据词 / 阈值 / 限定词 / 指向对象有无**丢失或走样**？ | 判据词一字不动；丢了即回补（锚点句就是判据骨架，只能换外壳） |
| ⑤ | **诱导**：有**题型名**暗示吗？有**指向性诱导**（指定设问/作答路径、自造举例、否定式植入）吗？ | 一律清除；去链保义、举例改占位或删 |
| ⑥ | **拼接**：与**同一份实发**里其他块拼在一起，整体看有无**重复语义 / 啰嗦语义 / 语义不一致**？**并逐段核对：段与段的边界是否清晰、段内结构是否清晰**（段界分明、段内分层有序，不把多件事挤在同一段）？ | 一判据一处正句，其余**引用化**（"判据见××条款，此处不另立"）；不一致处**仲裁化**并写明管辖域；结构混乱处拆段/分层，**但不许靠加段落来增字** |
| ⑦ | **位置与结构（排序）**（用户 2026-10-01 定序·⑦⑧对调）：**两层都要符合模型的遵守习惯**——**先看每一块／每一库内部**（块内先契约后细则、一段一主题、段界分明、同主题相邻），**再看拼接后的整份实发**（关键判据放首尾、长素材不与判据混排、同判据不拆到首中尾、越靠近生成动作处放越关键约束、开场短直入任务） | 不合则**重排**（不靠加字）；⑥ 管"重复/不一致"，⑦ 管"位置与结构与排序"，二者分开判 |
| ⑧ | **质量**（用户 2026-10-01 定序·⑦⑧对调）：照这条实发，模型产出的资料能否达到**高质量**（内容充实、可作答、可判分、体例自洽）？ | 拿不准的标"待真机"，并**标注判定层级**（纸面推演／程序校验／真机实测），不靠加长条款兜底 |

**逐条判定格式（留痕，写入 docs/review-reports/ 对应批次）**：`位置 | 原文 | ①…⑧ | 处置（留/压缩/引用化/门控/删） | 依据`。

### 六.3 判定权与依据纪律（2026-10-01 用户裁定 · 防"判例覆盖成文法"）

> 用户原话："如果你每一次都让我判断和决定，到下一次你就会忽略了我们原来的标准，延续了上一次的判断了吧？你会以为这是我给的新标准吧？还会导致偷懒，对不对？"
> 答：对。为防这四种走样，定如下纪律——**依据只能是文档条款，不能是"上次的口头裁定"**。

| 条 | 纪律 |
|---|---|
| D1 | **标准唯一在文档**：一切判定以本文件 §六/§六.2 与《修复准则-检查清单》为准；**口头裁定不自动成为标准**，不得据"上次说过可以"推断"这次也可以" |
| D2 | **口头裁定要长期生效必须入档**：由我把该裁定写成条款（并加机检或写入台账），未入档者视为**一次性个例**，不进入后续判定依据 |
| D3 | **只提两类问题给用户**：(a) 标准之间出现**真实冲突**；(b) 需要**产品/业务取向**而非技术判定的取舍。其余一律自判，不把判定责任推回 |
| D4 | **判定必留痕且可复算**：每条给出 `①–⑧` 判定 ＋ **依据（文档条款编号/判据锚点/测试名）**；禁止写"按上次的意思"作为依据 |
| D5 | **不得以个案当通例**：某次"为某 cell 破例"必须写明作用域与失效条件；无作用域声明的破例＝无效 |
| D6 | **标准被改动时先改标准再改实现**：任何与标准冲突的既有做法，要么改实现、要么走 D2 入档改标准，不得两边并存 |
