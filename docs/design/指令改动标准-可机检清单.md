# 指令改动标准（可机检清单 + 人工纪律）

> 用户裁定（2026-09-30）：把这一路的要求**固化成标准**，以后改动必须遵守；**能机检的做成测试守卫——没做到就让测试变红**。
> 用法：改指令（提示词/蓝图/规则/规格）后跑 `npx vitest run tests/config`，下列"硬锁"项违反即红。

## 二、单源标准（同一判据只准一份正句）

| # | 标准 | 机检方式 | 状态 |
| --- | --- | --- | --- |
| U1 | **判据级唯一出现**：每判据一处正句，其余**只能引用** | `tests/config/caliberSingleSource.test.js`（首批 3 判据：同题内形态一致／同卷形态统一／不得另起同性质整行短答载体） | 硬锁（分批推进中） |

## 四、人工纪律（不可机检，但必须遵守）

| # | 纪律 |
| --- | --- |
| H1 | **实发文本改动先经用户点头**（先给表，再动手） |
| H2 | **不猜、先取证**：根因优先；**不得用长句/加定语去逼近未定位的问题** |
| H3 | **不打补丁**：按全局看、按三维度（学段×学科×资料类型）看 |
| H4 | 每次改动跑**全量测试 + 构建**后再提交（CI 已代管） |
| H5 | **不擅自放宽守卫**：守卫误报时改自己的措辞或收窄守卫判据域，不迁就改动放宽 |

## 五、本清单自身的维护

- 新增标准 → 在 U1/U2 里加一个判据正则（收紧一个锁一个），或在 S 系列加断言；
- 阶段性目标：把 S6、M4、M5 三条"待机检"补成硬锁；U1 逐批把已核实冗余的判据收到"=1"。
