# 生成端复位工程 · 实施计划（2026-09-07）

依据：`docs/design/三线生成架构-设计准绳.md`（委托线/素材线/底线线已固话，本计划内一切改动先过准绳再动手）。
目标：把生成端从"单次巨型上下文直灌 + 后置检查驱动"复位为"对话式多轮（研读轮 → 委托轮一次成稿）+ 素材按需可查 + 程序只做形态/校验/报告"。
验收主线：本课《小数乘法和除法（二）》（苏教版六上随堂巩固）对话式流程 vs 现拼装式 的同模型 A/B 对照。

## 前提（未满足前不进入阶段 2 之后的实测）

- P1 云引擎可用并支持：长上下文多轮对话、工具调用（browse）、长输出（覆盖整份资料篇幅不截断）。需 API Key（环境变量注入，不落仓库）。
- P2 会话持久化与生成日志：研读轮/委托轮消息可查、可续、可重放（调试与审计用）。
- P3 基线绿：全量测试与构建通过；现有 A-101 相关修复与护栏保持不变（78 文件 1378+ 测试基线）。

## 阶段 0：盘点与基线确认（不动行为）

任务：
- 0.1 盘点生成链代码事实：`src/composables/useAiGenerator.js`（预算帽/系数/两次生成路径/浏览附件路径）、`GenerateModule` 相关界面（注入指令预览/编辑/类型范围设置/生成按钮）、素材装配（materialBlock/hits/kpText）、Step1 内容卡结构（contentCards/锚树/段类型枚举）。
- 0.2 盘点语英 Step1 分析产物字段（O1 依据）、现有预算系数公式（写进新成本模型）、现有截断检测与重试兜底位置。
- 0.3 输出《盘点清单》到 `docs/design/`，标出每处改造的入点与风险。
验收：盘点清单列出每个待改点的文件/行级入点、现状行为、目标行为三栏；无行为改动。

## 阶段 1：会话化编排器（基建）

任务：
- 1.1 建立生成会话模型：消息数组 + 轮次状态机（研读中 → 可委托 → 生成中 → 已出稿；缺料/校验失败可回流研读）。
- 1.2 消息追加接口：每步只追加一条消息（不构造最小上下文、不复制前轮）；超长历史压缩且替换（压缩产物替换旧消息，不叠加）。
- 1.3 browse 工具注册：白名单（仅本次覆盖范围内锚）、返回该锚绑定完整段（练习题原文不返回）、单次 ≤1 段（O3 默认）、越界拒绝。
- 1.4 预算/成本模型落地：研读成本（批数×批大小×系数档）+ 生成输出预算（≥完整篇幅硬约束，宁余勿缺；不够→显式提示换引擎/确认，绝不静默截断）。
验收：单测覆盖轮次状态迁移、消息追加不复制前轮、压缩替换语义、browse 白名单与练习段过滤、预算公式单元用例。

## 阶段 2：研读轮

任务：
- 2.1 研读编排：批粒度按委托覆盖模式自适应（命题型逐点精读批 / 梳理总结型章级结构批）；单批上限=分批阈值（O2 默认 ≤2500 字/批，超即拆批不切尾）。
- 2.2 批摘要产出与校验：点名⊆该批清单、引用可溯源（引用句须在绑定片段内命中或高相似）、非空；校验失败回流该批重读。
- 2.3 研读总账：批摘要合成覆盖点全集↔每点摘要/引用；程序校验通过才置"可委托"态；missing 锚 → 缺料诊断，研读不静默通过。
- 2.4 对账边界落实：对账只锁事实/依据层；创作层（情境/数据/设问）不受教材范围限制。
验收：整册勾选研读有界（峰值=单批）；整册×required 组合被契约层拒绝或提示分批；批摘要校验用例全绿。

## 阶段 3：委托书后移与一次成稿

任务：
- 3.1 现有注入指令功能保留照搬：三维度拼装预览/编辑/类型与范围设置/生成参数，仅时序后移到研读完成之后，动作语义=追加委托书消息。
- 3.2 委托书纯净化：渲染契约语法示例、vp 版面规则等程序性知识从委托正文移出（程序侧持有）；委托书目标 ≤ 千字级（角色/类型目的/栏目骨架/质量正句/覆盖点名清单/课标 cell 要点）。
- 3.3 一次成稿：追加委托书后模型单轮产出整份资料；废除程序分段/分栏/两次生成拼装路径。
验收：指令面板功能回归（原能力不丢）；委托书正文体积达标；单轮输出完整（无截断，截断检测兜底仅报告并回流重做）。

## 阶段 4：素材线前置改造

任务：
- 4.1 Step1 段类型枚举补"拓展/文化"类；锚范围性质判定（仅绑定拓展型段的锚 → 拓展锚，不进必覆盖清单）。
- 4.2 建议题型字段从模型可见面剥离（含 browse 返回物）；练习题原文不进研读主料与 browse。
- 4.3 锚命名校准与绑定质量（literal/semantic/chapter 分级），配合 O1 语英卡形态定型（盘点后实施）。
验收：A-101 循环小数族类锚不再进必覆盖清单；语英 content 型研读可用（O1 收口）。

## 阶段 5：职责切分落地（按底线线全表逐项核对）

任务：
- 5.1 程序介入点逐一过尺："改了语义变不变"——内容类程序改动清零；形态层项（空位归一去重/○ 归一/<u> 兜底/前言杂质/空白量补足）确认纯标记层。
- 5.2 校验报告类对齐：空条款/题号/分值/可作答/预填/空标签/重复截断/可数对象/单位/载体越界/无差别过宽/术语回潮/防照搬护栏（O5 默认阈值）——全部只报不改，报告路径统一（回流模型重做/交编辑）。
- 5.3 移除程序侧"代写/改内容"残余路径（若有）。
验收：全链无"程序产生语义内容"路径（代码审查 + 专项测试）。

## 阶段 6：端到端 A/B 验证

任务：
- 6.1 同模型（云引擎）双跑：A=对话式新流程（研读轮+委托轮一次成稿），B=现拼装直灌流程；同范围同类型（本课随堂巩固）。
- 6.2 编辑四问打分：覆盖落点、题型与情境多样性、课标符合度（事实层可溯源）、与教材原文相似度（护栏报告）——按 A-101 验收口径逐项对比。
- 6.3 依结果调档：研读批阈值、browse 步长、护栏阈值（O2/O3/O5）A/B 校准。
验收：A 在四问上全面不劣于 B，且在多样性/照搬两项显著优于 B；出具对照报告到 `docs/review-reports/`。

## 阶段 7：全量回归与收口

任务：
- 7.1 全量测试 + 构建绿；新增单测（轮次状态机/批校验/预算公式/护栏阈值/委托书体积）并入常驻套件。
- 7.2 更新既有契约测试（assemblyMatrix 等）以适配新流程口径（指令注入面、素材供给面）。
- 7.3 提交推送（`git commit -F` 多行信息 + push origin master）。
验收：仓库干净、全绿、推送完成；文档（准绳/计划/对照报告）留痕。

## 风险与对策

- 引擎能力不满足（无长上下文/工具/长输出）→ 阶段 1 前必须先验证 P1，不满足则暂缓实测，先完成可离线部分（编排器/校验/测试基建）。
- 研读轮成本上升 → 系数档位作为费用旋钮（默认低系数档粗粒度），完整性不受影响。
- 行为回归（原有 1378+ 测试）→ 每个阶段保持全量绿再进下一阶段。
- 与用户节奏冲突 → 每阶段结束给出验收摘要，阶段间设检查点（0/1/2/3 与 6 为硬检查点）。
