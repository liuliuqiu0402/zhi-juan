# 卷级守门引擎与写作修订轮（系统性根治方案）

> ⚠️ **废弃标注（2026-09-10 更新）**：本方案的**"写作修订轮"（模型整卷重写自纠）部分已废弃删除**——2026-09 实测两轮 100% 空转（约 10K+ token / 次，整卷总省略截断 → 判"长度异常"→0 修复、白烧 2 次长调用），且重写有篡改达标内容风险。
> **当前落地点（保留的只是"卷级守门"这半边）**：确定性守门检测 + 出报告，命中清单交编辑人工核对；程序不再自动重写、不再"模型自纠"。首段过程性自述句（确定性文本）由程序剔除。请以 [源头防线总览](../源头防线总览.md) 为准。
> 本文件仅存史备查——其中"修订轮/自纠循环"相关章节均已不适用，勿据此实现。

> 依据：2026-09-07 实测《小数乘法和除法（二）课时训练》全套产物体检（docs/review-reports/2026-09-07-课时训练-全局体检报告.md）
> 原则：根治不打补丁；发现靠确定性规则、程序只推进程与报告，不产生内容（"修订靠模型"原表述已随修订轮一并废弃）。

## 一、症状群 → 系统层缺口的收敛

实测 10 类症状：教材照搬泛滥（58 处）、卷内情境/算式/数据雷同、正文开头过程自述、概念题硬套情境、
参考答案可数对象中间量无单位、循环点载体协议缺失、覆盖对账虚假安全感、质量报告缺陷（重复条目/孤立"；"/info 混列/缺检测项）、
委托书预览未拆分、参考答案细节粗糙。

收敛为 3 个系统层缺口：

1. **写作无交付前自纠工序**——全部"省力路径"症状（照搬/雷同/自述/情境错配/细节不校验）同一病根：一次性写完即交付。
   研读轮已有"校验失败→回流重读"，写作侧没有对应机制。
2. **素材参考面直接暴露可照抄原文**——参考卡示范段整段可见，"变式"仅为弱措辞，照搬零成本且无沿用禁令闭环。
3. **程序卷级检测碎片化**——各检测各写各的：无统一报告结构、无去重、无算式/情境查重、无首段自述检测。

## 二、根治机制（与既有架构同构，非新补丁）

### 机制 A：卷级守门引擎（paperGuardEngine）
收敛全部**确定性**规则，输出结构化命中清单与分级报告：

| 规则 | 性质 | 来源/实现 |
|---|---|---|
| 教材照搬命中（≥8 字连续字面重合 / 原算式复用） | 确定性 | 现 antiCopyGuard 逻辑迁入；命中段进"禁用沿用名单" |
| 卷内算式重复（同算式 ≥2 次） | 确定性 | 正则抽取算式集合查重（新增） |
| 情境主题词频（同主题词 ≥3 题） | 确定性 | 主题词表 + 频次统计（新增） |
| 正文首段过程自述 | 确定性 | 首段正则（新增："已获取/已取到/现在编写/接下来/以下将/依据…命题"等） |
| 数据裂缝（可数对象小数等） | 确定性 | 现 contentSanity 逻辑迁入 |
| 覆盖缺漏 | 确定性 | 现覆盖对账逻辑（锚 vs 题面）迁入 |
| 形态/载体 | 确定性修复 | examValidator 形态级 fix 保留（不改语义内容） |

引擎统一产出：`{ hits: [...分级], bannedList: [...禁用沿用名单], reportText: 结构化报告 }`。
报告要求：去重（同文本合并计数）、分级（ℹ️ 信息 / ⚠️ 待修订 / 🔴 阻断）、分节（照搬/卷内重复/自述/裂缝/覆盖/形态）、
无拼接残符（修现"；"bug）。引擎**只报不改**（形态级 fix 除外，已界定为排版形态）。

### 机制 B：写作修订轮（生成端内自纠，≤2 轮）
正文/答案每次生成完成后：
1. 跑守门引擎 → 命中清单；
2. 清单非空 → 追加一条修订消息（同一 messages 会话）：给模型【命中清单】+【禁用沿用名单】+ 修订要求（自行决定改题面/换数据/换情境/删自述，全文回传修订版，不得声明代替修订）；
3. 复检（再跑守门）→ 命中减少到 0 或满 2 轮 → 交付；
4. 满 2 轮仍残留命中 → 原样交付 + 命中清单进【问题列表】报告（不静默、不无限重试）。

发现靠确定性规则（可信，规避"自产自评无意义"教训）；修订是模型（编辑）行为；程序不产生内容、不代改。
与研读轮同构：程序推进程、模型产出、校验回流、有限轮收口。

### 机制 C：素材沿用禁令闭环
- 守门照搬命中段（≥8 字连续）→ `bannedList`；
- 修订轮把 bannedList 交给模型：已命中的段/算式/数据组合不得再次沿用，须换数据换情境重写；
- 首次生成无历史名单 → 靠修订轮闭环自净；跨卷可携带（编辑确认后注入委托，防"改完又抄新段"）。

## 三、伴生收尾（同一改动内，不单独立项）

1. 委托书开头加"署名编辑身份锚"与交付前自审义务句（编辑者立场锚点，规则不再裸堆）；
2. 概念/规则/技能题脱情境要求从质量底线提为委托强约束（清单命中情境主题词频时由模型自行判断哪些题属概念题并简化情境）；
3. 循环点协议：循环小数的书写空位按"学生手写循环点"设计（答案给循环节说明），题干不依赖程序渲染上点；
4. 可数对象取整措辞：答案中可数对象最终结果须取整并给出取整理由（去尾/进一）；
5. UI 委托书预览拆分：编辑者委托书正文与程序规则（渲染/质检/学段要求）分区分层展示，规则区默认折叠。

## 四、验收

- 同一教材单元实测：正文【问题列表】无"教材照搬"命中（或 ≤2 轮修订后归零）、无卷内算式重复、无情境主题 ≥3、
  首段无过程自述；报告无重复条目与残符；覆盖对账仍全绿；
- 全量单测 + vite build 绿；修订轮开关不影响直灌/浏览两通道；
- 机制 B 修订轮失败兜底不阻断交付（报告可见），不无限重试。
