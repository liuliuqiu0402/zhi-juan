## 一、为什么要动结构行

属主 2026-10-17 的判断：蓝图结构**本来就是参考**（可增可减），一旦把"参考分值"和"序号"摆在结构行里，参考就变成了骨架与指标：

- **序号**（`三、填空`）给了一个"有编号的层"的样板，模型倾向在下一层也编号——与本轮"小题号"问题同源。
- **分值**（`｜参考分值 24分`）是一个精确整数；只要它在场，该大题的**判分处个数**就被 `Y÷X` 反推锁定（24 有 1/2/3/4/6/8/12 等约数，所以这种锁定永远不会以"除不尽"的形式暴露）。选 X=1 只是最常见的落点。

结论：要让结构只当清单，**编号与分值都得可撤**，缺一个都还会被当骨架。

## 二、改动一：结构行撤序号

`buildStructureText` 三处渲染全部去掉中文序号（大题行、小学"大类层"行、英语"部分层"行）。先后关系由**行序**表达，不再由序号表达。

断言改准：`tests/recipe/blueprintInjection.test.js` 五处（`/^一、积累与运用｜…/m` → `/^积累与运用｜…/m` 等）、`tests/recipe/promptLibrary.test.js` 两处；原用例标题"大题去前缀、序号全卷连续"改为"大题去前缀、结构行不带序号"；并把其中一条 `toContain('一、')` 改为**反向锁**（`not.toMatch(/^[一二三四五六七八九十]、/m)`）＋正面断言"大题名与分值仍在"。

## 三、改动二：结构分值三档开关

`buildStructureText(bp, { withScore = true } = {})`——分值段（大题行、大类层行、部分层行）统一受 `withScore` 控制。

UI 接在既有"结构来源"开关旁（`GenerateModule.vue`，`structureMode`，2026-10-16 属主裁定、9 类全开放、纯增量）：

| 档 | 值 | 结构 | 分值 |
|---|---|---|---|
| 固定结构（默认） | `blueprint` | 注入 | 带（行为与改动前一致） |
| 固定结构·不带分值 | `blueprint-noscore` | 注入 | 不带——只留板块名＋命题要求 |
| 自由组织 | `free` | 不注入 | — |

两处 exam 调用点改为 `buildStructureText(applyScoreAdjust(bp), { withScore: structureMode.value !== 'blueprint-noscore' })`；守卫 `freeStructureMode.test.js` 的"默认分支串形"断言同步改准（仍锁"exam 默认走蓝图"）。

> 备注：`structureMode` 是**既有**通道（`buildFreeStructureInstruction` 已实现"自由组织"），本次只加一档，未新造开关体系。

## 四、改动三：质检"不丢题"不变量（测试期）

`tests/utils/auditNoLoss.test.js`。定位：**零运行期代码、零运行期噪音**，只在跑测试时生效。

两条硬判据（对全部样本）：H1 题块数量不得减少；H2 任何题块不得被清空。题块认法：`<p class="question">` 内去标签后的文本。

为什么按"分支"造样本而非按"学科"：风险不由学科产生，而由**质检里某条会改写正文的分支**产生；学科不增加分支。按学科铺样本＝按分类学铺样本，30 条里可能 25 条走同一路径（项目 D9/D15 明禁"以抽样代替真判定"）。
