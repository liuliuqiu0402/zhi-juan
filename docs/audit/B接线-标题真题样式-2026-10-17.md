# 留痕：B 接线——标题真题样式（渲染期，2026-10-17）

> 提交：`0a667cf`（原语 `composeScoreLabel`）→ 本次（接入 `title-detail-fix`）
> 定位：`src/utils/examValidator.js` 新增 **1.6b 段**（紧接 1.6「大题标题分值形态归一」之后、2「大题级」之前）

## 一、B 到底做什么（与 A 的分工）

| 侧 | 职责 | 依据 |
|---|---|---|
| A（模型侧，已落 `1685de2`） | 标题写「（共X分）」；全大题同单价时把单价写在各独立题干后；**先定单价、再乘判分处数** | 分值条 `576` / 账目 `577` |
| B（程序侧，本次） | 只做**写法**归一：标题已是「（共X分）」且题内唯一单价时，补成真题写法「（每〈计分对象〉X分，共Y分）」 | `title-detail-fix` |

**B 不改数**：`Y` 取标题既有总数（模型给的），单价取题内既有标注（模型给的），
`composeScoreLabel` 只做「单价×个数」拼装，**不做除法**。程序不重算、不回写——
"程序即使把分值凑齐了，也可能与内容不自洽"（属主 2026-10-17 裁定）。

## 二、四条硬门（缺一不动）

1. 该大体内「每X分」恰好出现**一次**——模型按 `576` 逐题干标注时，标题再补就成一题三处并存，故跳过。
2. 单价恰好一种。
3. 总数能被单价整除，且个数 > 1——个数为整数，故**不存在除不尽**；只有一处时「每X分，共X分」是废话。
4. 题内那一处**不是已经完整的「每X分，共Y分」**——已完整即该处已承载单价与总数，标题再补就是重复。

任一不满足 → 一字不动（不硬造单价、不硬凑总数、不写除不尽的小数）。

## 三、验证

| 用例 | 断言 | 结果 |
|---|---|---|
| 单价仅一次 + 可整除（24÷1） | 标题变成「（每空1分，共24分）」并留 info 记录 | 绿 |
| 0.5 分档（4÷0.5=8，整数） | 「（每处0.5分，共4分）」 | 绿 |
| 单价逐题干重复（模型已按分值条标注） | 标题不动 | 绿 |
| 单价多于一种（不等分） | 不动 | 绿 |
| 5÷2 不可整除 | 不动 | 绿 |
| 题内无单价 | 不动 | 绿 |
| 已是真题写法 | 幂等（跑两遍不再叠加） | 绿 |
| 题干那处已是完整「每X分，共Y分」 | 不动 | 绿 |

测试文件：`tests/utils/titleScoreStyleB.test.js`（8 例）、`tests/utils/composeScoreLabel.test.js`（5 例）。
