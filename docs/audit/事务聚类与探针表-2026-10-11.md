## 二、批 A 探针详表（根因链：**T01 ＋ T02 ＋ T18 ＋ T04**，共 30 条）

### T01 唯一性与数量

- **决定句（应为唯一正句）**：唯一性只判「**两处可互相替代**」；**同型多题、同一知识点多题、材料被多题共用，均为正规做法**；**量（题量/条数）由内容产出，不作生成输入**。
- **唯一落点**：`src/config/promptLibrary.js` `QUALITY_BASE`「内容唯一性」条（T01 正句**只此一处**）。
- **L1 计数锚**（在**注入快照**上计；✅ = 2026-10-11 修毕后的实测）
  - **正句**（期望恰 **1**）：`两处可互相替代才算重复` → ✅ 1
  - **清零**（期望 **0**·字面模式，含审计漏记项）：`同一大题内同型小题也只作一题`｜`不扎堆反复出现`｜`尤其不得雷同`｜`题量以委托书为准`｜`不得复现相同材料`｜`同一大类内不得拆成多道大题`｜**`同一知识点在同一资料内不得重复考查`**（⚠️ 审计**漏记**，实为 practice／special／reading **3 处**） → ✅ 0
  - ⚠️ 另删同类**空指针**：`本块规定考什么、多少题、多少分`（【卷面结构】块头；〔349〕后结构不给题数）
  - ⚠️ 另删**跨块指针**：`题目层面的唯一性以正文【质量底线】…条为准`（`validatorRules:duplicate-content-fix`；[G91](#)）
- **L2 互斥探针**（同现即红）：`只作一题` ✕ `同型多题`；`不得复现相同材料` ✕ `材料被多题共用`
- **期望**：正句在注入文本内**恰 1 次**；上述清零字面 **0 次**；且**不得**出现"同型多题＝缺陷"的读法
- **验收命令**：
  ```
  node scripts/snapshotInjection.mjs type=exam subject=语文 stage=primary_high grade=三年级
  # → T01·正句: 1（期望 1）✓ ／ T01·清零: 0（期望 0）✓
  ```

### T02 编号·序号·组标题

- **决定句**：题号只由**编号对象口径**（哪些题各自构成独立作答单位）决定；**号怎么排不作统一规定**；**大题序号（一、二、三…）全卷连续**（属主裁定：不放开）。
- **L1 计数锚**（为 0）：`全卷连续`（凡指**小题号**处）｜`按栏目（组）分别起编`｜`不得跳号`｜`同号同序`
- **L2 互斥探针**：`小题号…全卷连续` ✕ `号怎么排不规定`
- **期望**：小题号编法类字面 0；大题序号连续条**仍存在且唯一**
- **验收命令**：
  ```
  npx rg -n "小题号.{0,20}连续|按栏目.{0,6}起编|不得跳号|同号同序" src/ | Measure-Object -Line
  ```

### T18 考查方式与思维要求

- **决定句**：**技能训练型重在准确熟练；理解运用型重在推理、说理与迁移**（按题型分档，不再一句统管）。
- **L1 计数锚**（为 0）：`不靠记忆`｜`逐题各有考查侧重`｜`不以机械套算`
- **L2 互斥探针**：`不靠记忆` ✕ `口算/默写/字词（技能训练）`
- **验收命令**：
  ```
  npx rg -n "不靠记忆|逐题各有考查侧重|不以机械套算" src/ | Measure-Object -Line
  ```

### T04 空位·作答载体·篇幅

- **决定句**：**待答之处＝空位之处＝载体之处（三处同位）**；强调用途的 `<u>` 与空位载体 `<u class="blank-N">` 是两回事；形态只由**学科·学段规格**定。
- **L1 计数锚**（为 0 或改写）：`正文不出现 <u>`（**须限定为"强调用途"**）｜`本条优先于一切通用表述`｜`以本条为准`｜`以其为准`｜`格内留空`｜`学科协议`
- **L2 互斥探针**：`正文不出现 <u>` ✕ `blank-N`（空位载体）；`填符号…圆括号` ✕ `比较大小…○`
- **验收命令**：
  ```
  npx rg -n "正文不出现 <u>|本条优先于一切通用表述|以本条为准|以其为准|格内留空|学科协议" src/ | Measure-Object -Line
  ```

## 八、判准升级（属主 2026-10-11 追问）：**"一处"指注入后的文本，不是源码**

- **属主判准**：给模型的文本里，**一个事务只有一处表述**才算清晰；**分散（哪怕措辞一致）必生牵扯与理解不一致**。
- **现状澄清**：项目现有"单源"多为 **源码单源、注入多处**——**重复发生在装配环节**：
  | 例 | 源码 | 注入后 |
  |---|---|---|
  | `QUALITY_BASE` | 一处常量 | 经【质量底线】**与**守门兜底**两条通道**各一次 |
  | 【题目自洽】①–⑰ ↔【尾约束·三域】 | 两处 | **同事务两整套**（G83） |
  | "不重复" | 三处 | 三处都进文本（G81） |
- **两条动作（T01–T19 一律适用）**：
  1. **合并到唯一落点**：每事务在本表登记**唯一段落落点**；其余位置**删**——且**不得留"见【X】"引用字样**（对模型而言引用同样是噪音与分散；引用只为源码维护，应在**注入时展开为空**）。
  2. **验收对象改为"注入后的最终 prompt"**：L1 锚在**注入快照**上计数，**同一事务决定句＝1**（而非源码 grep 的 0／多）。
- **后果（诚实）**：此前以"源码零出现／单源常量"作验收，**口径偏松** → **须重取基准**。
- **前置工具**：做一支 **注入快照工具**（把某类型的**最终 prompt** 落成文本文件），批 A 的 L1 基准**在快照上重取**。
