4. **既有裁定可被"今天的诊断"推翻**（2026-10-11 属主原话）：
   > "原来弄尾约束是因为模型总是执行不到位，找不到原因；现在已查出基本是**过度约束、多处牵扯、促规范不精准**导致的执行不到位。**你现在来看要怎么处理呢？不要受原来裁定的影响判断。**"
   ⇒ 凡"审计判语 ↔ 在先裁定"相抵处，一律**按今天的诊断重判**，不得以"既有裁定／专锁"为挡箭牌；**但须在台账留痕理由**（范例：台账〔362〕的 G83/G75/G76）。

## 五、执行者纪律（从 2026-10-11 起生效）

1. **三段式**：开工先贴【本轮声明】（本事务／成员条／边界／验收物／本轮预算够不够做完）；收工贴【本轮交底】（改动清单／**验收命令＋原始输出**／commit hash）。**无命令输出不得称"完成"。**
2. **不够就不做**：单轮预算不足完成一个事务组时，**明说"本轮不做"**，不做到一半。
3. **批次＝事务**：同一事务的多条**必须一次改完**；跨事务耦合须在聚类表标注，按拓扑序做。
4. **探针前置**：每事务的 L1 计数锚 ＋ L2 互斥探针**与修复同时写**，不事后补。
5. **先声明后动手**：不得先改再解释。
6. **换人签核**：每完成一大批，**换新会话**只拿"注入后的完整 prompt 文本"重审（L4）——承认自检有盲区。

## 六·五、指令协议（属主 ←→ 执行者，2026-10-11 立）

**最短用法：只说口令**（当前阶段与下一步由本文件承载，无需你复述规范）。

| 口令 | 执行者必做 |
|---|---|
| `开工` / `继续` | **读本文件** → 贴【本轮声明】（事务／成员条／边界／验收物／预算判断）→ 动手 → 贴【本轮交底】 |
| `交底` | 改动清单 ＋ **验收命令原文 ＋ 原始输出** ＋ commit hash（**无输出不得称完成**） |
| `验收 <事务名>` | 跑该事务 **L1 计数锚 ＋ L2 互斥探针**，给原始输出 |
| `回归` | **L1＋L2 全量回归** ＋ 全量测试 |
| `换审` | 提示属主开新会话，**只提供"注入后完整 prompt 文本"**供重审（L4） |
| `停` | 立即停手，把现状写进本文件（未提交须注明），**不半程推进** |
| `裁定：<一句话>` | 落进本文件"四、属主裁定"区，**永不擅改** |
| `查 <问题>` | **只答／只查，不改任何文件** |

**长指令模板**（需精确定向时）：
```
【事务】<名>
【要改】<条号／文件>
【不许动】<边界>
【验收】<命令或行为>
【预算】<只做这些／做完即停>
```
开头加 `按锚文件办` 即启动全部纪律。

**四问（随时可发，防糊弄）**：① 这条有命令输出吗？② 属哪个事务、成员都有谁？③ 会不会与已收的某条相抵？④ 这轮做了多少、剩多少、锚更新了吗？

**属主不必再做**：复述规范、贴标准、提醒"促规范"——均在本文件与 `附·4` 内。属主只需给**事务与验收物**，或**指出执行者又犯了什么**。

**报缺陷的省事格式**：哪一类／哪一份 ＋ 那段原文 ＋ 期望形态。
