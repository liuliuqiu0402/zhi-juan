# 多模态与文本模型切换配置指南

## 📊 **当前配置架构**

### 模型分工策略

```
┌─────────────────────────────────────────────┐
│           您的硬件环境: 8GB 显存              │
├─────────────────────────────────────────────┤
│                                             │
│  🖼️ 多模态模型 (OCR/图片识别)                │
│     → qwen3-vl:8b (固定使用 Ollama)          │
│     → 显存占用: ~5-6GB                       │
│     → 调用时机: 教材分析、模板分析            │
│                                             │
│  📝 文本模型 (AI 生成/分析)                  │
│     → 重型任务: qwen2.5:14b 或 7b            │
│     → 轻量任务: qwen2.5:7b                   │
│     → 显存占用: 7B≈4GB, 14B≈8GB             │
│     → 调用时机: 命题生成、蓝图规划、质量审查   │
│                                             │
└─────────────────────────────────────────────┘
```

## ✅ **切换机制验证结果**

### 1. **多模态模型（qwen3-vl:8b）**

**特性**:
- ✅ **始终使用本地 Ollama**，无论文本引擎是 Ollama 还是 DeepSeek
- ✅ **自动检测就绪状态**: 每次调用前通过 `/api/ps` 检查模型是否在内存
- ✅ **智能预热**: 检测通过后额外等待 5 秒确保完全稳定
- ✅ **重试机制**: 最多重试 3 次，每次等待 25 秒

**调用流程**:
```javascript
// 1. 获取配置
const config = await getMultimodalConfig();
// 返回: { engine: 'ollama', model: 'qwen3-vl:8b' }

// 2. 检测模型就绪
await checkModelReady(imageBase64, 3, 'multimodal');

// 3. 预热等待
await new Promise(r => setTimeout(r, 5000)); // 5秒

// 4. 执行 OCR
const result = await fetch(`${config.baseUrl}/api/chat`, {...});
```

**结论**: ✅ **多模态模型调用非常稳定，无需担心切换问题**

---

### 2. **文本模型（7B ↔ 14B 切换）**

**特性**:
- ✅ **支持动态切换**: 可在设置界面选择 7B 或 14B
- ✅ **按任务类型自动选择**:
  - 重型任务（命题生成、蓝图规划）→ `ollamaTextModel`
  - 轻量任务（格式化、简单分析）→ `ollamaLightModel`
- ✅ **支持自定义专用模型**:
  - 题目生成专用: `ollamaQuestionGenModel`
  - 质量审查专用: `ollamaReviewModel`
  - 分析提取专用: `ollamaAnalysisModel`

**调用流程**:
```javascript
// 1. 根据任务类型获取配置
const config = await getCurrentEngineConfigEnhanced('generation');
// 返回: { engine: 'ollama', textModel: 'qwen2.5:14b', ... }

// 2. 检测模型就绪
await checkModelReady(null, 3, 'text');

// 3. 智能等待空闲
await smartWaitForModel(2000, 8000); // 2-8秒

// 4. 执行 AI 调用
const result = await callAI(prompt, { taskType: 'generation' });
```

**结论**: ⚠️ **已修复缓存问题，现在切换后立即生效**

if (oldHeavyModel !== newHeavyModel) {

## 📋 **推荐配置方案（8GB 显存）**

### 方案 A: 稳定优先（推荐新手）

```javascript
{
  ollamaTextModel: 'qwen2.5:7b',      // 重型任务用 7B
  ollamaLightModel: 'qwen2.5:7b',     // 轻量任务用 7B
  ollamaMultimodalModel: 'qwen3-vl:8b' // OCR 用 8B
}
```

**优点**:
- ✅ 显存占用可控（7B + 8B ≈ 9-10GB，Ollama 会自动卸载）
- ✅ 切换速度快，不易爆显存
- ✅ 适合连续分析多页教材

**缺点**:
- ⚠️ 命题生成质量略低于 14B

**适用场景**: 日常使用、批量处理教材

---

### 方案 B: 质量优先（推荐专业用户）

```javascript
{
  ollamaTextModel: 'qwen2.5:14b',     // 重型任务用 14B
  ollamaLightModel: 'qwen2.5:7b',     // 轻量任务用 7B
  ollamaMultimodalModel: 'qwen3-vl:8b' // OCR 用 8B
}
```

**优点**:
- ✅ 命题生成质量最高
- ✅ 蓝图规划更合理
- ✅ 质量审查更准确

**缺点**:
- ⚠️ 显存紧张（14B + 8B ≈ 13-14GB）
- ⚠️ 需要手动管理模型卸载
- ⚠️ 不适合连续调用

**适用场景**: 生成重要考卷、需要高质量输出

**操作建议**:
```bash
# 使用前加载 14B
ollama run qwen2.5:14b

# 使用后卸载
ollama stop qwen2.5:14b

# 或者设置 keep_alive 时间短一些
# 在 apiConfig.js 中修改:
options: {
  keep_alive: '5m'  // 5分钟后自动卸载
}
```

---

### 方案 C: 混合模式（云端+本地）

```javascript
{
  currentEngine: 'deepseek',           // 文本任务用 DeepSeek
  deepseekApiKey: 'sk-xxx',            // 您的 API Key
  ollamaMultimodalModel: 'qwen3-vl:8b' // OCR 仍用本地 Ollama
}
```

**优点**:
- ✅ 文本任务质量最高（DeepSeek 云端大模型）
- ✅ 不占用本地显存（文本任务）
- ✅ OCR 仍保持本地隐私

**缺点**:
- 💰 需要付费（DeepSeek API）
- 🌐 需要网络连接

**适用场景**: 对质量要求极高、有网络环境

## 💡 **最佳实践建议**

### 1. **日常使用推荐配置**

```javascript
// 设置 → AI 引擎
重型模型: qwen2.5:7b       // 平衡质量和速度
轻量模型: qwen2.5:7b       // 复用同一个模型，减少显存占用
多模态模型: qwen3-vl:8b    // 固定不变
```

**理由**: 
- 7B 对于大多数任务已经足够
- 减少模型切换带来的显存压力
- 适合 8GB 显存环境

---

### 2. **重要任务临时切换**

当需要生成重要考卷时：

```bash
# 步骤 1: 切换到 14B
# 设置 → 重型模型 → qwen2.5:14b → 保存

# 步骤 2: 卸载 7B 释放显存
ollama stop qwen2.5:7b

# 步骤 3: 生成考卷
# 回到生成模块，执行生成

# 步骤 4: 完成后切回 7B
# 设置 → 重型模型 → qwen2.5:7b → 保存
ollama stop qwen2.5:14b
```

### 4. **优化 keep_alive 设置**

如果觉得模型频繁加载/卸载影响体验，可以调整保持时间：

**位置**: `src/composables/useAiGenerator.js`

```javascript
// callMultimodalAI (2780行)
options: {
  keep_alive: '30m'  // 默认 30 分钟
}

// 如果想更快释放显存，改为:
keep_alive: '5m'  // 5 分钟后自动卸载
```

**建议**:
- 8GB 显存: `5m` - `10m`
- 16GB+ 显存: `30m` - `60m`
