3. 逐环节详细发现

3.1 指令与提示词构建 关键断链

正常
任务行 + 模板正文（EXAM_BASE / PRACTICE_BASE / TYPE_BASES）+ 渲染契约（[IMAGE]/[GRAPH]/公式）+ 校验前约束（buildValidatorPrompt）+ 蓝图注入/教辅结构注入。
模板匹配
按 学段×学科×类型 逐级降级匹配（buildInjectionInstruction）。
作答空/括号/横线规范
已写入 FORMAT_RULES 并注入。
作文格位置
已写"先题干后格子"到 FORMAT_RULES 并注入。
// buildInjectionInstruction 形参（promptLibrary.js:350-353）——注意：没有 propositionStyle！
const { template, grade, subject, unit, genTypeLabel, structure, fullScore, duration, extra, label, semester, academic } = opts;
根因 R1 · 情境框架断链
生成端 hasContext 判定用正则读instruction字符串里的"命题风格：unified_context"（useAiGenerator 5170-5174）。但 buildInjectionInstruction 把 propositionStyle 参数丢弃了，规则：
  • exam 因内置 EXAM_BASE 第 50 行硬编码了"命题风格：unified_context"，正则能命中 → 才会建统一情境。
  • 非 exam（practice/reading/summary/preview/dictation/errorbook 等）模板没有这句，且 UI 默认的 context_fusion 根本没被注入 → 非考试类资料的情境框架代码路径（5176-5372）整体被跳过，直接不生成任何情境 → 产出易退化成"孤立堆题"，即"无情境"。
  • 该字面量被设计成"若不需要统一情境，删除本行即可"（人可删），删除后情境能力瞬间消失，属"配置文本驱动代码行为"的反模式。

3.2 整卷正文生成（generateFullPaperNatural 段1）

生成方式
paperGenerateMode（split/once/auto），默认 auto：纯题型(exam/practice/special/review)→split；知识型(reading/summary/preview/dictation/errorbook)→once。
温度
split 用 paperTemperature(0.7)；once 用 (0.7+0.3)/2=0.5 折中。
预算
split 用 paperBodyMaxTokens(32768)；once 用 paperOnceMaxTokens(49152)；思考模式 ×thinkingBudgetMultiplier(2)。
后处理
cleanSectionHtml → normalizeBlankMarkers → normalizeIndents。
截断
finish_reason=length / reasoning_capped + 尾部启发式 → 自动续写一次。
思考耗尽
reasoningChunkCount≥20000 或 reasoning_capped 且正文为空 → 强制关闭思考重试一次。
已带电工程：截断续写、思考耗尽降级、预算按路径读取，均比旧版可靠。

3.3 答案页生成（段2）

输入
正文完整转纯文本 htmlToPlainText(content, answerContextMaxChars=24000)，不是"空输入/凭记忆"，杜绝答案与正文不符。
提示词
ANSWER_ROLES（exam=阅卷专家+评分标准，其他=教辅编辑+解析）+ ANSWER_FORMAT_SPEC（HTML 规范）。
温度
answerTemperature(0.3) 低温严谨。
预算/续写
answerMaxTokens(16384)×思考倍数，allowContinuation:true（截断自动续写），推理上限 20K，思考耗尽强制关思考重试一次。
once 补包
once 模式模型漏答案区 → 正则有缘即自动触发独立答案页补生成；<h2>参考答案 缺 answer-section 包裹时补包。
不可见性
独立调用仍无答案区 → 透出到生成报告【问题列表】+ 排查方向，不再静默丢。
说明：答案页"缺失"问题当前代码已有多层防御与可见性。曾因"23368 字符截断 → docxBuilder 丢答案区"（过去 allowContinuation=false 未续写）已改为 allowContinuation:true。dist 产物已用字符串字面量核验确实包含这套逻辑。
风险 R2 · 大概率复发点：ansInContent = /<h2[^>]*>参考答案|answer-section/ 只认 <h2>。若模型输出 <h3> 或"答案""解析"等其它措辞，once 模式会误判"无答案"→ 又会独立再生成一份答案页，可能造成"正文+独立答案页"并存（正文已含答案区时部署）。建议统一为"包容器/结构"判定，而非措辞正则。

根因 R3 · 能力写好了没接上线：
  • subjectValidators.runHardValidators/applyAutoFixes（数学/物理/化学/语文别字等学科正确性校验）从未接入主链路 → 学科硬伤无法在生成后拦截，只能靠模型自觉；这正是"修了别的 bug、学科内容错仍复发"的常见来源。
  • examFixer.fixExamFormats（场景标签移除/标题明细化）未调用，与 examValidator 的 title-detail-fix 重复但实际只剩 examValidator 生效。
  • buildHtmlGenerationPrompt（格式化模板块）从未在主路径调用 → 主生成并不依赖该模板，属死代码。
  • 「括号与横线混用」「上下文情境连贯性」没有任何确定性后处理规则：全押在模型 prompt 自守 + 高温(0.7)上 → 间歇不稳，正是"反复修"的重灾区。

3.5 作文格位置纠正（2j-5a）启发式脆弱

// examValidator.js 972-1009
const kwRe = /看图写话|写话|习作|作文|写作/;
// 向前找最近含关键词的"题干"，找不到就向后找并插入其后
根因 R4 · 作文格位置：位置纠正靠"关键词正则"找所属题干。两个致命弱点：
  • 关键词不全：题干若用"照样子，画一画写几句话""续写""给图画配文"等未列入 kwRe 的措辞，格子不会被挪动，就仍会出现在题干上方 → "作文格跑题头上"复发。
  • 错配风险：格子在其所在题题干缺失时，向后找"最近含关键词的段落"，可能撞上后面另一题的题干，把格子粘到错误题目上（内容错位）。
  • 根子上，位置应由"模型输出结构"（题目节点内嵌格子）保证，而不是事后按模糊关键词搬运。

3.6 再生成 / 差异化（diffKps 与跨会话记忆）

再生成
失败自动重试走同一条 generate()；"重新生成蓝图"是另起分支只出蓝图。
差异化
从指令读"已覆盖知识点"→ diffKps 注入；跨会话由 unitPaperMemory 读历史题目摘要 → 加"≥70% 不同"要求。
作文格"消失"
不是被删除——再生成＝重新整卷生成，用户之前在旧卷上的任何编辑（含增删格子）不会被保留，整卷被新内容替换，故观感为"格子消失/跑位"。且新增内容会再次经受 2j-5a 的脆弱搬运，可能换位置。

5. 结构性根因（为什么总在"猜测修复"）

R5 · 单体 + 窄启发式 = 每次修一处，别处在别种措辞下复发

useAiGenerator.js 294KB、GenerateModule.vue 440KB、examValidator.js 62KB，三者强耦合。整卷输出的结构（标题/题号/括号/横线/连线/作文格/答案区）全部由模型在 0.7 温度生成 HTML，再靠一串"正则/DOM 启发式"事后修正。每上报一个 bug 就加一层启发式；启发式只命中一种措辞，换个说法同一类问题立刻回来。这是"重复折腾、猜测修复"的架构级根因，无法靠继续加补丁根治。

R6 · 关键决策被"可删的指令字面量"驱动，与 UI 配置脱钩

命题风格（情境框架）由指令字符串正则触发，而 UI 的 propositionStyle 选项在 buildInjectionInstruction 里被丢弃；"已覆盖知识点"差异化同样从字符串解析。UI 配置与代码行为分叉 → 用户以为选了 context_fusion/两次生成，代码却没照做。此类"配置与行为不一致"是最大隐藏雷区。

R7 · 能力未接线（死代码）+ 未提交大重构 = 假安全感

runHardValidators/applyAutoFixes/fixExamFormats/buildHtmlGenerationPrompt 写好了却不被调用；同时有 13 个文件的大改（常量体系 MAX_TOKENS→getTaskMaxTokens、默认 split→auto、extractQuestionList→htmlToPlainText）未提交、未做整链验证。子单元测试通过 ≠ 端到端链条正确，因为没有端到端结构不变量测试。

6. 修复优先级与方案（止住"猜测修复"循环）

P0 · 建立"端到端结构不变量"回归防线（治本，必须先做）

用一个 fake callAI（可注入"作文格在题前/括号横线混用/答案区缺失/无情境"等指定坏样例），跑完整 generateFullPaperNatural()，断言四条硬不变量：

  1. 答案区存在：最终 content 必含 answer-section（或在问题列表透出明确原因）。
  2. 作文格在所属题干之后：按"题目节点"维度判断，而非关键词搬运。
  3. 无括号×横线混用：（_____） / （_ _） 等非法形态 count=0。
  4. 情境框架已注入：按资料类型断言 contextFramework 非空。

作用：以后任何 patch 都要先过这四条链条不变量，否则直接标红 —— 从机制上杜绝"改了不生效/悄然回归"。

P0 · 情境框架改由资料类型显式驱动，废除指令字面量正则

  1. buildInjectionInstruction 增加并透传 propositionStyle；把"命题风格：{style}"作为确定注入文本。
  2. generate() 的 isUnifiedContext/isContextFusion 改为接收 params.propositionStyle（GenerateModule 已把 style 传下来，只是没接进指令），并给非 exam 类型也建 context_fusion 框架。可选一张 type→style 默认映射，让映射走配置而非正文。
  3. 移除 EXAM_BASE 中"删除本行即可"的字面量对代码行为的控制。

P1 · 把"反复发作"的三处改成确定性后处理

  1. 括号/横线归一：在 contentCleaner 增加确定性子程序——统一（英文半角括号+全角空格）形态，检测并清除括号内下划线；这是规则库或 cleaning 层的纯函数，可单测。
  2. 作文格位置：改为"题目节点内嵌"判定（在 <p class="question"> 内找所属题干），不要跨题用关键词找；课时内无法归属时宁可不动也不错配（加抽检提示）。
  3. 答案区判定：用包容器/结构（answer-section 或 含"参考答案|答案|解析"标题节点）判定，不单靠 <h2>参考答案，消除 once 模式双答案区风险（R2）。

P1 · 接通已写好的能力，清点死代码

  1. 把 subjectValidators.runHardValidators/applyAutoFixes 接入 auditExamPaper（或其后）作为学科硬 GATE（数值/化学方程式守恒/语文别字等）——零新增成本、直接补齐学科正确性。
  2. 决定 fixExamFormats/buildHtmlGenerationPrompt 去留：要么删除，要么接入；避免"规则库注册空洞"。

P1 · 治理：提交 + 构建同步自检

  1. 把当前 13 文件未提交改动先提交固化，避免"工作区形态与上次会话不一致"导致的假回归。
  2. 加一条构建自检脚本：构建后 grep dist 关键字符串（[answer-diag]、paperOnceMaxTokens），输出"dist 与 src 是否同步"；每次改 src 必须 rebuilt，防止又出现"改了 src 忘 build 以为没修好"。

关于"再生成丢格子"的预期引导

再生成＝整卷重新生成，旧卷用户编辑（含作文字格增删）不保留，属产品行为而非 bug。建议：再生成前明确提示"将整卷替换，未保存的手工修改会丢失"；或在再生成时保留作文格配置（学段格宽/列数）继续应用，避免"格子口径又变回默认"。作文格数字标注仍要注意：Word 中增删格子后需重新导出。

7. 给你的下一步建议（按顺序）

  1. 不要继续在 2j-5a / FORMAT_RULES 上叠话术和正则；先做 P0 的端到端结构不变量测试，把"复发"变成可被回归测试捕获。
  2. 优先修 R1（情境断链）与 R2（答案区判定），这两处是"无情境"和"答案双区/结构错"的直接原因。
  3. 提交当前未提交的 13 文件改动并重建 dist，之后每次改动都跑构建自检。
