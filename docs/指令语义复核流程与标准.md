# 指令语义复核流程与内容复核标准（不能 CI 的部分，固定流程执行）

> 定位：与 CI 断言分工。能确定化校验的进 `tests/`（assemblyMatrix 三维度逐句审计、sourceControl 课标出处受控等）；语义判断（措辞是否严谨、课标转述是否忠实、条款是否必要/是否诱导）走本流程。
> 原则：初检靠一次语义复核，此后回归靠 CI——复核发现的问题修复后必须尽可能固化为新 CI 规则，防止回潮。

## 一、分工边界（能 CI 就 CI）

| 检查类别 | 归属 | 落点 |
|---|---|---|
| 486 条完整指令逐条拼装、必含条款两栏、类型签名、类型专属词不广播、科段锚整段+逐句、蓝图 120+54 逐条闭环、空条款、句级重复、外包/旧壳黑名单、术语（考点仅 exam） | CI | `tests/recipe/assemblyMatrix.test.js` |
| 课标出处受控（54 科段 source 前缀受控清单、非空、正文句读、键对齐） | CI | `tests/config/sourceControl.test.js` |
| 卷面蓝图结构校验（分值闭合等） | CI | `tests/recipe/blueprintGuard.test.js` |
| 上述之外的一切"好不好/是否忠实/是否必要" | 语义复核（本流程） | `docs/review-reports/` 留痕 |

## 二、复核对象与批次规划

对象 = 四库 + 课标要点中**去重后的唯一条款/要点句**（不是 46,510 句重复遍历，去重后规模一个数量级更小；去重口径同 assemblyMatrix 的 `sentencesOf`）。

批次划分（一轮语义复核 = 一个批次，登记后执行）：

| 批次 | 内容 | 复核侧重 |
|---|---|---|
| A | 课标语段：SUBJECT_STAGE_EXTRAS 54 科段要点 | 忠实度、出处、自洽、层级表述 |
| B | 主指令通用条款段（创作要求/输出格式/质量底线/作答空间/书写载体/卷面自洽/输出约定等） | 编辑性、冗余矛盾、去诱导、术语 |
| C | 教学蓝图 120 条学科定制栏目注（+ 通用默认 9） | 可操作性、递进性、与要点单源、类型贴切 |
| D | 卷面蓝图 54 条（大题结构/分值/说明） | 结构合理性、学段适配、课标贴切 |
| E | 渲染契约 / 版面质检规则条款 | 职责边界（不外包压制模型）、协议自洽 |

批次 A–E 完成后可进入常态化：任一库内容变更 → 走对应批次复核 → 修复 → 固化 CI。

## 三、四问复核标准（每问按 红/黄/绿 判定）

判定级别：红 = 必改（会产出错误/违规内容）；黄 = 建议（可留痕跟踪，不阻断）；绿 = 通过。

### Q1 整体指令能否达到编辑者编辑要求（内容 + 排版要素）

- 红：条款只给方向不给可执行要件（"要生动""要合理"无锚）；任务词与作答形态语义脱节（如要求"写在横线上"却无书写位要求）；要素清单项缺失（对照 CONTENT_MUST/LAYOUT_MUST 之外的"该类还应有的要素"）。
- 黄：要素齐全但措辞冗余可压缩；示例过具体可能限制生成。
- 绿：要素齐全、可执行、按类型收敛。
- 反例（历史事故）："按书写惯例输出对应作答书写载体"——把形态交给模型语感，语义真空；"由排版层补足"——模型不输出空白。

### Q2 整体指令内是否冗余、矛盾

- 红：同指令内相同句 ≥2（样板尾句重复——已修复并 CI 锁 ≥16 字）；同一对象既"严禁 X"又"必须 X"；跨库同义双轨（A 单一事实源）；承诺性词与能力词互相打架。
- 黄：近义表述（非整句相同）可合并。
- 绿：无。
- 反例：蓝图栏目注样板尾句"要求具体可操作、按认知层次由浅入深递进"重复 2-3 次/条（307/486 指令，已根修）。

### Q3 是否符合课标要求

- 红：与 2022 义教 / 高中课标（2017/2020）内容相抵触（如把某学段目标前置到低学段）；无出处或出处不受控（CI 已锁）；转述偷换限定词（"会"变"掌握"、把课标"了解"写成"灵活运用"）。
- 黄：出处正确但提炼范围偏大/偏小；要点与要点之间跨科段同义漂移。
- 绿：转述忠实、限定词一致、出处可溯。
- 复核依据：该科段要点声明的 `source`（如"2022义教数学·第二学段学段目标"）对应的课标原文；转述是否保有限定词与层次。

### Q4 是否符合已固化审核基准（A 单源 / B 学段学科类型收敛 / C 去诱导 / D 模型职责 / E 宁缺毋滥 / F 双向护栏 / G 措辞=数据层 / H 预览=导出 / I 全量回归+契约）

- 红：职责外包句（"渲染层负责/程序自动补/按答案长度倒推"类）；跨学科广播（数学的量纪律进语文）；术语违规（非考试上下文用"考点"）；诱导模型空泛声明代替覆盖。
- 黄：样板化套话可保留但无信息增量；示例句可能封闭模型选择面（列举载体清单）。
- 绿：符合基准 A–I。
- 反例：跨学科污染（"数据真实可感/单位换算严谨"曾进 QUALITY_BASE 污染全学科）；"声明≠覆盖"（开头声明覆盖但未出题）。

## 四、流程步骤（固定）

1. **S1 登记**：在 `docs/review-reports/` 建批次清单（`batch-<A|B|C|D|E>-<序号>.md`），列出复核范围（来源文件/条目数/组合口径）。
2. **S2 导出输入**：按上表批次取唯一条款/要点句，标注 `库 | 科段 | 类型 | 原文` 四元组，作为复核输入。
3. **S3 逐句判定**：评审模型对每句按第三节四问给判定（红/黄/绿），只针对该句与其语境（所属组合类型/学科）判定，禁止跨句扩散。
4. **S4 问题清单**：统一格式输出（见第五节）；每个红/黄问题必须给"修改建议"。
5. **S5 人工裁决**：红 = 必改；黄 = 采纳或驳回并留痕原因；对"是否属考试上下文/是否可接受同义反复"等口径分歧在此裁决并记入口径记录。
6. **S6 修复与固化**：改源后先跑对应 CI；凡能确定化表达的新规则（新黑名单词、新锚点、新受控前缀）立即补进 CI 用例，防止回潮。
7. **S7 通过门**：该批红 = 0（含已裁决"接受风险"记录）；CI 全量绿；产物与裁决留痕后批次关闭。

## 五、问题清单格式（每行一个问题）

```
[判定级别:红|黄] [问题编号:B-2026-09-001] [位置:库=promptLibrary 主指令 | 科段=全部 | 类型=question]
[原文]（该句完整原文）
[问] Q1|Q2|Q3|Q4
[问题] 一句话说清（含为什么错/违规基准哪条）
[建议] 修改方向（可给替换文案）
[裁决]（人工：采纳/驳回+原因）
```

## 六、产物与留痕

- 批次清单与问题清单：`docs/review-reports/batch-*.md`。
- 修复提交信息引用问题编号（如"fix(prompt): B-2026-09-001 …"）保证可追溯。
- 口径变更（如新增受控课标前缀、新豁免词）记入本文档"口径记录"一节，并同步 CI 清单。
